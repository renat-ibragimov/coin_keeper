в `legacy/data/coinkeeper-2026-08-06.db`: если таблица пустая после года работы — функция
в MVP не идёт.

## Входит в MVP

### Аутентификация
- **Открытая регистрация с первого дня** по email и паролю
- Обязательное подтверждение email: аккаунт неактивен до перехода по ссылке
- Восстановление пароля по ссылке из письма
- Вход, выход, обновление токена, смена пароля
- Ограничение частоты запросов и honeypot в форме регистрации
- Данные коллекции привязаны к пользователю

Подробности — `07-auth.md`. Отправка почты через внешний SMTP — `10-infra.md`.

### Каталог
- Список с фильтрами: страна, год, номинал, группа (обиходные / памятные / коллекционные),
  металл (драгоценный / не драгоценный), наличие в коллекции
- Поиск по названию, стране, году, каталожному номеру
- Карточка позиции: характеристики, фото аверса и реверса, история цен, экземпляры в коллекции
- Постраничная выдача — 3063 записи нельзя отдавать одним куском

**Общий каталог доступен пользователю только на чтение.** Его наполняет администратор и
системная задача по каталогу НБУ. Правило из исходного ТЗ — «внешние источники не создают
каталожных записей» — теперь распространяется и на пользователей.

### Личные позиции каталога
- Создание, редактирование, удаление своей позиции, если нужного выпуска нет в общем каталоге
- Свои фотографии к ней
- Личные позиции участвуют в фильтрах, поиске, сериях, комплектности и статистике владельца
  наравне с общими
- Видны только автору

Это штатный путь, а не запасной: «не нашли монету в каталоге — заведите свою или
импортируйте выгрузку». Модель — `02-data-model.md`, правила — `04-business-rules.md`, п. 2.

### Коллекция
- Добавление экземпляра к позиции каталога: количество, дата, цена, валюта, продавец, заметка
- Редактирование и удаление
- Фильтр «есть в наличии» / «не хватает»

### Серии
- Список серий по странам
- Сводка: всего позиций, собрано, осталось, процент, сумма покупок, оценка по текущим ценам

### Деньги
- Потрачено на монеты, сопутствующие расходы, итого
- Текущая оценка коллекции по последним ценам
- Курсы НБУ: текущие и исторические на дату покупки
- Расходы по категориям (справочник категорий сохраняем целиком, см. `02-data-model.md`)

### Цены
- **Общий каталог: центральное обновление раз в сутки** системной фоновой задачей,
  источник UA-Coins. Пользовательской кнопки «обновить цену» для общих позиций нет
- **Личные позиции: обновление по требованию владельца** — одной монеты или пачкой по своим
  позициям, с прогрессом и возможностью остановить
- Ручной ввод цены по любой видимой позиции
- История цен графиком
- **Валидация цены до записи** — см. `05-integrations.md`

Снимки центральной задачи видны всем; снимки из ручного ввода, обновления личных позиций и
Excel-импорта видны и учитываются в оценке только у автора (`04-business-rules.md`, п. 7).

**Честная граница покрытия:** автоматические цены в MVP покрывают только **украинскую** часть
каталога — UA-Coins других стран не даёт. Цены по США и СССР приезжают из Excel-выгрузок
uCoin и вводятся вручную. Numista, который в исходном ТЗ должен был закрыть остальные страны,
в MVP не делаем (нужен персональный API-ключ).

### Импорт
- Excel-выгрузка uCoin (`.xlsx`) с предпросмотром, поиском дублей и отчётом
- Импорт монеты с uCoin по URL
- Импорт раздела каталога uCoin по URL

Импорт **создаёт только личные позиции**. Совпало с общим каталогом — экземпляры
привязываются к общей записи, ничего не создаётся. Общий каталог импортом не пополняется
(`04-business-rules.md`, п. 3).

### Фото
- Загрузка своих изображений аверса и реверса
- Автоматические превью
- Замена и удаление

### Дашборд
- Позиции каталога и экземпляры, комплектность, осталось собрать
- Потрачено / оценка / разница
- Курсы USD и EUR с датой
- Недавно добавленное, ближайшие к завершению серии

### Настройки
- Язык интерфейса (украинский / английский)
- Источники каталога uCoin
- Экспорт коллекции в Excel

## Откладываем на после MVP

| Функция | Почему |
|---|---|
| Цели коллекционирования (`collection_goals`) | 0 записей за год использования |
| Предложения о покупке (`purchase_offers`) | 0 записей |
| Продажи (`sales`) | 0 записей, но экран в интерфейсе был |
| Разновидности (`catalog_variants`) | 0 записей; режим «разновидности включены» из ТЗ не проверялся на практике |
| Журнал изменений (`audit_log`) | 0 записей |
| Грейдинг (компания, номер, оценка) | поля есть, данных нет |
| Numista API | требует персонального ключа, в legacy так и не заработал |
| «Повышение» личной позиции в общий каталог админом | сначала посмотрим, что за позиции заводят пользователи |
| Марки и другие предметы | явная заглушка в исходном ТЗ |
| Годовые PDF-отчёты | не критично для веба |
| Мобильные приложения | после веб-MVP |

Схему под отложенное закладываем сразу (таблицы создаём), API и интерфейс — нет.
Так потом не придётся переделывать миграции.

## Явно вне проекта

- Оффлайн-режим и локальная база на устройстве
- Синхронизация с десктопом
- Портативная сборка
- Восстановление старого Electron/Tauri-кода

## Критерий готовности MVP

Пользователь регистрируется сам, подтверждает адрес по письму, видит общий каталог из
3063 позиций с фотографиями, отмечает свои монеты, заводит личные позиции для того, чего в
каталоге нет, вносит покупки, видит сколько потратил и сколько стоит коллекция сейчас,
импортирует выгрузку с uCoin. Цены украинской части подтягиваются сами раз в сутки.
Всё это — с телефона через браузер.

Функциональность MVP простым языком, без схемы и эндпоинтов, — `12-user-facing-scope.md`.
