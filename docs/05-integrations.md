# 05. Внешние интеграции

Четыре источника:

| Источник | Что даёт | Роль |
|---|---|---|
| НБУ, API курсов | курсы валют | системный, ежедневно |
| НБУ, каталог нумизматической продукции | **общий каталог по Украине**, официальные фото | системный, еженедельно |
| UA-Coins | цены по украинским монетам | системный, ежедневно |
| uCoin.net | импорт **личных** позиций пользователя | по запросу пользователя |

Ключевое разделение: общий каталог и его цены наполняют **только системные фоновые задачи**
по официальным и надёжным источникам. uCoin остаётся источником пользовательского импорта
и общего каталога не касается (`04-business-rules.md`, п. 2).

Эталонные реализации — `legacy/reference-code/pricing.ts` и `ucoin-import.ts`.

---

## 1. НБУ — курсы валют

Самая простая и надёжная интеграция. Работала без нареканий.

**Эндпоинт:**

```
GET https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json
GET https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json&date=YYYYMMDD
```

Ответ — массив объектов, нужны поля `cc` (код валюты), `rate`, `exchangedate`
(в формате `DD.MM.YYYY`, конвертировать в ISO).

Берём только `USD` и `EUR`.

**Правила:**

- Курс на дату кешируется в `exchange_rates`, повторно не запрашивается.
- Если на дату курса нет (выходной, праздник) — берём последний опубликованный **до** этой даты.
- Обновление текущих курсов — фоновой задачей раз в сутки.

**Что исправить относительно legacy:** там досинхронизация недостающих дат шла по одной дате
за HTTP-запрос, начиная с 2009 года — это тысячи вызовов. НБУ отдаёт диапазон одним запросом
(`exchange?json&start=YYYYMMDD&end=YYYYMMDD&valcode=USD&sort=exchangedate&order=desc`),
использовать его.

Документация: https://bank.gov.ua/ua/open-data/api-dev

## 2. uCoin.net — импорт личных позиций пользователя

Самый сложный источник и единственный, который работает по запросу пользователя, а не по
расписанию.

**Роль изменилась относительно legacy.** В десктопной версии uCoin был основным источником
каталога — оттуда пришли все 3063 позиции. В веб-версии он **не является источником общего
каталога**: любой импорт с uCoin создаёт только **личные** позиции того пользователя, который
его запустил (`04-business-rules.md`, п. 3). Причины две:

- права на данные и фотографии uCoin нам не принадлежат (`06-media-storage.md`);
- Cloudflare делает серверный обход по расписанию неработоспособным (см. ниже).

Каноническим источником по Украине вместо uCoin стал каталог НБУ — раздел 3.

### Два пути импорта

**A. Excel-выгрузка.** Зарегистрированный пользователь uCoin выгружает свою коллекцию в `.xlsx`.
Так пришли 2824 из 3063 позиций. Формат — лист `Collection`, колонки по позиции:

| Колонка | Поле |
|---|---|
| 1 | страна |
| 2 | серия |
| 4 | номинал |
| 5 | год |
| 6 | разновидность |
| 7 | название |
| 10 | рыночная цена |
| 11 | каталожный номер |

Строка пропускается, если пусты страна, номинал или год. Разбор — `openpyxl`.
Эталон: `legacy/reference-code/excel-import.ts`.

**B. Скрейпинг сайта.** По URL монеты или раздела каталога. Так пришли 239 позиций.

### Почему нужен headless-браузер

uCoin отдаёт содержимое через JavaScript и стоит за Cloudflare. Обычный HTTP-запрос получает
заглушку. В legacy это решалось скрытым окном Electron, которое рендерило страницу и снимало
данные из DOM.

**В Python — Playwright с Chromium.** Простой `requests`/`httpx` не подойдёт.

Логика legacy, которую надо воспроизвести:

1. Загрузить страницу с обычным браузерным User-Agent.
2. Снять данные из DOM (см. ниже).
3. Если в тексте страницы есть `just a moment` / `enable javascript` / `cloudflare` —
   подождать 1,5 с и повторить, до 45 секунд.
4. Если не пробилось — вернуть ошибку с предложением пройти проверку вручную.

Legacy показывал пользователю окно браузера для ручного прохождения Cloudflare
(`openUcoinSession`, `openUcoinUnblock`, `resetUcoinSession`, страница
`legacy/reference-code/ucoin-login.html`). **В серверной версии этот путь недоступен** —
пользователь не видит браузер на сервере.

**Отсюда решение, зафиксированное окончательно: планового серверного обхода uCoin нет.**
Не «по возможности откажемся», а норма архитектуры. Скрейпинг uCoin запускается только
пользователем, по конкретному URL, и наполняет только его личные позиции.

Для единичных запросов пользователя проверка Cloudflare чаще всего проходится ожиданием
(шаг 3 выше). Если не пробилось — возвращаем понятную ошибку и предлагаем путь A. Вариант
с передачей пользовательских cookies uCoin оставляем на потом: он ближе всего к legacy, но
требует хранить чужие сессионные данные. Резидентный прокси — дорого и проблему не решает.

**Путь A (Excel) — основной и надёжный, путь B — вспомогательный.**
Это меняет приоритеты по сравнению с legacy, где скрейпинг считался равноправным.

### Что снимается со страницы

Из `extractPage`:

- `info` — все строки таблиц вида `ключ: значение` (характеристики монеты)
- `priceText` — первый текстовый узел, целиком совпадающий с `^\d[\d\s.,]*\s*(₴|грн\.?|UAH)$`
  и не содержащий `=` или `x`
- `heading` — `<h1>` или текст вида `Название, ГГГГ`
- `images` — все `<img>` с абсолютным `src`, `alt`, натуральными размерами
- `coinLinks` — `a[href*="/coin/"]`
- `pageLinks` — ссылки пагинации внутри `/catalog/`

Аверс и реверс выбираются по `alt` (`obverse|аверс`, `reverse|реверс`), при отсутствии —
по порядку и размеру изображений.

### Нормализация URL

```
canonicalUrl:  протокол → https, hostname → uk.ucoin.net, якорь убирается
sourceKeyFor:  hostname → ru.ucoin.net, ключ = ucoin:<hostname><pathname>[?tid=<tid>]
```

Разные языковые поддомены uCoin — одна и та же монета. Без нормализации получаются дубли.

### Обход разделов

Собрать ссылки со всех страниц пагинации, затем обойти монеты. Между запросами
**пауза 450 мс** — сохранить обязательно, это защита и от блокировки, и от нагрузки на
чужой сервер. При переносе на сервер паузу имеет смысл увеличить.

Прогресс сохраняется в `ucoin_catalog_sources`: `last_scanned / inserted / updated / skipped`.

## 3. НБУ — каталог нумизматической продукции

**Канонический источник общего каталога по Украине.** Официальный сайт Национального банка,
раздел нумизматической продукции (`bank.gov.ua`, `numismatic-products`).

Отдельного API у раздела нет — страницы отдаются обычным HTML, без JavaScript и без
Cloudflare. Парсится так же, как UA-Coins: `httpx` + `selectolax`. Playwright здесь не
нужен.

**Как устроен каталог (проверено разведкой 2026-09-03, см. раздел 8).** Страница
`/ua/uah/numismatic-products/souvenier-coins` — это форма поиска; сами результаты отдаёт
один POST-эндпоинт:

```
POST https://bank.gov.ua/ua/component/source/searchSouvenierCoinResult
     page=1&perPage=100&category[]=Coin
```

`perPage` принимает 5/10/25/100; фильтры `serie[]`, `metal[]`, `nominal[]`, `quality[]`,
`from`/`to` (дата `ДД.ММ.ГГГГ`, минимум `07.05.1995`), `search`. **Пустые значения
фильтров ломают запрос (404)** — отправлять только те, что реально используются.
`category[]=Coin` даёт 1048 карточек (11 страниц), `Souvenir` — 92 (ролики, буклеты).

Отдельных страниц монет нет: каждая карточка листинга уже содержит всё — название,
серию (тег), «Номінал», «Дата введення в обіг» (или «Дата випуску»), «Матеріал»,
«Тираж (оголошений/фактичний), шт.» вида `2500/2500`, художника, скульптора, массу,
диаметр, категорию качества, гурт и описание. Идентификатор карточки — `id` в пути
превью (`/media/coins/{id}/avers.jpg`), буквенный код — в пути полноразмерного файла.

Изображения: превью `/media/coins/{id}/avers.jpg|revers.jpg` (около 200 px, ~60 КБ) и
полноразмерные `/files/coins_images/{code}a.png|{code}r.png` (1600×1600 PNG, 3–4 МБ);
`{code}a0.png` — дополнительный ракурс, `{code}u.pdf` — буклет, есть не у всех.

### Что берём

- официальное название выпуска на украинском → `title_uk`;
- официальные изображения аверса и реверса;
- номинал, год, металл, проба, вес, диаметр, гурт;
- тираж — объявленный и фактический;
- серия и дата ввода в обращение.

### Задача обхода

Системная фоновая задача, **раз в неделю**. Новые выпуски подхватываются автоматически:
НБУ публикует их в этом же разделе.

Алгоритм:

1. Обойти разделы каталога, собрать список выпусков.
2. Сопоставить с **активными** позициями общего каталога по ключу
   **номинал + год + название** (нормализация названия — та же, что у UA-Coins ниже).
   Архивные из сопоставления исключаются: разархивирование — решение человека, а не задачи.
3. **Совпало** → обогатить запись по правилу `COALESCE(новое, старое)`: заполняются только
   пустые поля, уже заполненное не затирается. Исключение — `title_uk` и официальные фото:
   они замещают данные из uCoin, потому что это первоисточник.
4. **Не совпало** → добавить как новую **системную** запись (`created_by = NULL`).

Изображения скачиваются к себе (`media_files.source = 'nbu'`, `storage_key`), а не
хотлинкуются. Они публичные и постепенно вытесняют uCoin-фото украинской части каталога —
см. `06-media-storage.md`.

### Задача никогда не удаляет записи

Это правило без исключений. Позиция, ранее заведённая из каталога НБУ, могла разойтись по
чужим коллекциям — удалить её значит разрушить чужие данные.

Если ранее созданная из НБУ позиция **исчезла из официального каталога** или выпуск отменён,
задача её **архивирует**: `is_archived = true`, `archive_reason = 'снята с выпуска НБУ'`
(`04-business-rules.md`, п. 10). Экземпляры, покупки и история цен владельцев при этом
сохраняются полностью.

Архивирует задача только записи, которые сама и создала (по `source_key` с признаком НБУ).
Позиции из мигрированной базы владельца и заведённые администратором вручную она не трогает:
их отсутствие на сайте НБУ ничего не доказывает. Раздел покрывает выпуски с 1995 года
полностью (по годам 1995–2018 его счёт совпадает с ua-coins и Википедией один в один), но
с 2022 года недорогоцінні монеты в нём числятся только как «… у сувенірному пакованні» —
отдельной записи «голой» монеты нет, и конвейер должен считать такую карточку самой монетой.

Обратной операции у задачи нет: разархивировать может только администратор. Если позиция
вернулась на сайт, она попадёт в отчёт как «архивная запись снова найдена в источнике»,
и решение принимает человек.

### Отчёт задачи

По итогам обхода задача пишет отчёт, а не молча правит базу:

```
scanned      — сколько выпусков разобрано на сайте
matched      — сопоставлено с активными позициями
enriched     — реально обогащено (заполнены пустые поля, заменены фото)
inserted     — добавлено новых системных записей
archived     — архивировано как снятое с выпуска, с перечнем id и названий
duplicates   — вероятные дубликаты: кандидаты на ручную архивацию админом
warnings[]   — неразобранные страницы, спорные сопоставления
```

**Вероятные дубликаты** — отдельная строка отчёта, не автоматическое действие. Если один
выпуск с сайта уверенно сопоставился с двумя и более позициями каталога, это почти наверняка
дубликат, накопленный за время импортов из uCoin. Задача их не сливает и не архивирует сама:
слияние с перепривязкой экземпляров отложено на после MVP (`01-scope-mvp.md`), а до тех пор
администратор решает вручную и закрывает лишнюю позицию архивацией с причиной `'дубликат'`.

### Границы

Раздел покрывает только Украину. США и СССР в общем каталоге — наследие мигрированной базы
владельца, пополняются администратором вручную. Numista и uCoin источниками общего каталога
не являются.

Документация раздела: https://bank.gov.ua/ua/numismatic-products

## 4. UA-Coins — цены по украинским монетам

**Источник цен общего каталога.** Обычный HTML без JavaScript, парсится напрямую
(`httpx` + `selectolax`), Cloudflare нет — поэтому именно он, а не uCoin, годится для
планового серверного обхода.

**Но сайт не отвечает из-за пределов Украины** (разведка 2026-09-03: TCP-таймаут с машины
разработчика и с американского fetch-сервиса, при этом DNS отдаёт и IPv4, и IPv6). Это
означает, что с сервера в Hetzner он, скорее всего, тоже недоступен, — **проверить первым
делом при боевом прогоне разведки**. Пока это не проверено, планировать суточную задачу по
ua-coins нельзя; запасной путь — копии в Wayback Machine (`web.archive.org`), которые
разведка использует как fallback и которые для страницы `/ua/catalog/all/all` отстают
от сайта на недели.

Полезные страницы (URL подтверждены):

| Страница | URL | Что даёт |
|---|---|---|
| весь каталог одной таблицей | `/ua/catalog/all/all` | 1060 строк, все годы — один запрос вместо тридцати |
| годовой каталог | `/ua/catalog/all/{год}` | те же строки за год; есть `?sort=` |
| то же по-русски | `/catalog/all/all`, `/catalog/all/{год}` | **русские названия с теми же id** — ключ к нашим `title_original` |
| серии со счётчиками | `/en/categories/all`, `/ua/categories/all` | 38 серий: всего / недорогоцінні / дорогоцінні / суммарный тираж |
| страница монеты | `/ua/list/{id}-{slug}` | русское название под заголовком, таблица «Дата / Номінал / Метал / Маса / Діаметр / Тираж / Ціна НБУ», серия, цена дня |
| план выпуска НБУ | `/ua/nbu-plan-list` | по годам 2017–2026 |

Строка таблицы (`td[data-title]`): «Дата» (`дд.мм.гггг`, в новой вёрстке внутри
`span.desktop`), «Номінал» (`5 грн.`, `200000 крб.`), «Тираж тис.» — в тысячах, вида `75/50`
(объявленный/фактический), «Назва» со ссылкой `/ua/list/{id}-{slug}`, «Вартість дд.мм.гггг»
(число с тонкими пробелами, стрелка тренда или «немає даних»). Серии и металла в таблице
нет — только на странице монеты и на странице серий. В таблицу входят и наборы, и монеты
в сувенирной упаковке отдельными строками.

Изображения: `/images/coins/{id}_obverse.jpg` и `_reverse.jpg` (старый вариант, 5–60 КБ,
есть у всех), `/images/coins/small|middle|big/{id}_{side}.webp` и `big/{id}_{side}.png`
(у новых выпусков; наличие у старых — проверить живым прогоном, из-за недоступности сайта
разведка это не подтвердила).

### Центральная суточная задача

Системная фоновая задача обновляет цены **активных** позиций общего каталога раз в сутки.
Снимки пишутся с `created_by = NULL` и видны всем (`04-business-rules.md`, п. 7).

Архивные позиции задача пропускает: их история цен замораживается на момент архивации.
Разархивированная позиция вернётся в очередь сама, отдельного действия не требует.

Обход идёт порциями, с паузой между запросами и честным User-Agent. Полный проход за раз не
обязателен: очередь строится по давности последнего снимка, позиции без цены — первыми.

Цены личных позиций центральная задача **не трогает** — их обновляет владелец по требованию,
тем же парсером, снимками с `created_by = <пользователь>`.

### Режимы разбора страницы

Два режима, из `pricing.ts`:

**A. Сохранённая ссылка.** Если у позиции `source_url` содержит `ua-coins.info` — грузим
страницу и берём цену с неё.

**B. Поиск по годовому каталогу.** `https://www.ua-coins.info/ua/catalog/all/{год}`,
дальше построчный разбор таблицы:

- ячейка `data-title="Назва"` → ссылка и название
- ячейка `data-title="Номінал"` → номинал

Совпадение по названию — после нормализации: нижний регистр (`uk-UA`), NFKD, удаление
`’'`"«»()[]{}.,:;!?–—-`, схлопывание пробелов. Считается совпавшим, если строки равны или
одна начинается с другой плюс пробел.

Номинал сравнивается как число (первое число в строке, запятая → точка).

Если точного совпадения по названию, году и номиналу нет — `not-found`, ничего не пишем.

User-Agent в legacy: `CoinKeeper/0.1 personal collection`. Оставить честный
идентифицирующий UA.

## 5. Numista

В ТЗ значился основным источником цен для всех стран кроме Украины. **Так и не заработал** —
требует персонального API-ключа, без него запросы не принимаются. В базе нет ни одной цены
из Numista.

В MVP не делаем. Если понадобится — ключ получает каждый пользователь сам и вносит
в настройках, централизованный ключ на сервисе противоречит их условиям.

Документация: https://en.numista.com/api/doc/index.php

## 6. Валидация цены — обязательный слой

Главный урок legacy. Цены писались без проверки, ошибки чинились миграциями постфактум,
итог — заведомо мусорные данные в базе.

### Известные баги парсера

Восстановлены по названиям миграций и бэкапов:

| Симптом | След в схеме |
|---|---|
| Склеенные числа (`12001500` вместо `1200`) | `sanitize-ucoin-glued-prices` |
| Год приклеился к цене (`2018450` вместо `450`) | `sanitize-ucoin-year-prefixed-prices` |
| Вместо цены монеты — стоимость металла | `before-bad-ucoin-metal-price-fix`, `-cleanup` |
| Отдельные позиции с явно неверной ценой | `before-ucoin-svdb-price-correction`, `before-ucoin-1914-p-cent-price-correction` |

Существующий фильтр в `parsePriceUah` уже отбрасывает строки с `**`, `=`, `x` — сохранить.

### Проверки перед записью

Минимальный набор:

1. **Диапазон.** Цена в разумных пределах (например, 1–1 000 000 грн). Ноль и отрицательные —
   отклонять.
2. **Не год.** Число, совпадающее с годом выпуска или лежащее в 1900–2100 при отсутствии
   явного символа валюты, — подозрительно.
3. **Длина.** Больше 7 цифр подряд без разделителей — почти наверняка склейка.
4. **Отклонение от истории.** Если у позиции уже есть цены и новая отличается от медианы
   последних снимков более чем в N раз (начать с 10) — не писать, вернуть `rejected`
   и пометить для ручной проверки.
5. **Валюта явно определена.** Нет `₴`/`грн`/`UAH` в исходном тексте — не цена.

Проверки применяются одинаково ко всем путям записи: центральная суточная задача,
пользовательское обновление личной позиции, ручной ввод, Excel-импорт.

### Что делать с непрошедшей ценой

Не писать в `market_price_snapshots`. Вернуть `status: rejected`, сохранить сырой ответ
источника в лог (`raw_payload` у отклонённой попытки или отдельная таблица) — чтобы можно
было разобраться, а не гадать.

### Существующие данные

3938 снимков цен из legacy-базы содержат неизвестную долю мусора. При миграции —
прогнать через те же проверки и пометить подозрительные. Подробности в `09-data-migration.md`.

## 7. Общие правила для всех источников

- Все обращения к внешним сайтам — только в фоновых задачах, никогда в HTTP-обработчике.
- Таймаут на запрос, ограничение числа попыток, экспоненциальная задержка при ошибках.
- Пауза между запросами к одному хосту.
- Честный User-Agent.
- Плановый серверный обход разрешён только для источников без Cloudflare и с приемлемыми
  условиями использования: НБУ (курсы, каталог) и UA-Coins. Для uCoin планового обхода нет —
  только запуск пользователем, см. раздел 2.
- Ни один внешний источник не создаёт записей в **общем** каталоге, кроме системной задачи по
  каталогу НБУ (раздел 3). Пользовательский импорт создаёт только личные позиции.
- Любой ответ внешнего источника сохраняем сырым до разбора: без этого отладка невозможна.

## 9. Украинский конвейер (этап 4.5, часть B)

Разведка из раздела 8 только смотрела — конвейер пишет. Ничего не пишется без `--apply`.

### Что изменилось против раздела 8

**ua-coins.info отвечает.** Разведка ловила таймаут и работала по копии Wayback; при
прогоне 2026-09-04 сайт ответил живьём (`access: live`), и цены берутся с него напрямую.
Режим `--ua-coins auto` пробует живой сайт и сам уходит в архив, если тот молчит.

**У НБУ есть английская версия.** Тот же POST-эндпоинт под `/en/`, идентификаторы карточек
совпадают. Отсюда официальные `title_en` и английские названия серий — без перевода.

**Полноразмерные фото есть не у всех.** `{code}a.png` / `{code}r.png` отдаются для 389
карточек из 1048; у остальных только превью `/media/coins/{id}/avers.jpg` около 198 px.

**Обиходных памятных монет в нумизматическом каталоге нет.** 10-гривневые «обігові
пам'ятні» с 2022 года (ССО, ТрО, «Ми сильні. Ми разом. <область>») — не нумизматический
продукт, и карточки у самой монеты нет. Есть карточка **ролика**: `category=Souvenir`,
номинал 250 грн, название «Ролик обігових пам'ятних монет "X" (у ролику 25 монет)».
Карточка называет монету, датирует её, показывает её аверс и реверс (`{code}a.png` —
это монета, а не упаковка) и через номинал ролика задаёт её номинал: 250 ÷ 25 = 10.
Конвейер читает монету с карточки ролика (25 карточек, 2022–2026); это чтение, а не
выдумывание. Ровно этого не хватало, чтобы «Області України»/«Ми сильні» вообще получили
кандидата на мосту.

**Номинал НБУ пишет сокращённо** — «1 грн», «250 грн», не «1 гривня». Разборщик
`app/reference_data/denominations.py` этих сокращений не знал, и каждая созданная запись
оставалась без `denomination_id`. **Материал НБУ пишет по-украински** — «срібло»,
«нейзильбер», «біметалеві із недорогоцінних металів»; словарь материалов собран из
русских строк uCoin, поэтому `metal_kind` оставался `unknown`. Список значений у НБУ
закрытый (девять, из фильтра формы поиска), поэтому он размечен явно, а не угадывается.

### Шаги

Порядок — порядок зависимостей и порядок runbook:
`bridge → series → gaps → repair-gaps → merge → titles → photos → prices`.
Каждый шаг запускается отдельно (`--steps`), повторный запуск ничего не дублирует.

**bridge — какая наша запись какая монета.** Кластер из трёх источников (та же
union-find-склейка, что в разведке) — единица правды. Два пути внутрь:

- уже имеющаяся ссылка **любого из трёх источников**: строка `price_source_links`,
  `source_key` (`nbu:<id>`, URL ua-coins) или URL последнего общего снимка цены — ссылка
  не догадка, и таких 594 плюс все записи, созданные шагом `gaps`;
- скоринг кандидатов того же года (±1) и номинала.

Ссылок ua-coins раньше было мало не потому, что других нет, а потому что читались только
они. Запись, созданная шагом `gaps`, несёт `source_key = 'nbu:<id>'` — это карточка, с
которой она сделана, и её нельзя сравнивать по названию с нашей одноимённой записью:
именно так 42 из 62 позиций второго прогона попали в ревью «сами против себя».

Скоринг — суть шага. Наши названия пришли из русской локали uCoin, все три источника пишут
по-украински, и посимвольного отношения мало. По порядку:

1. с названия снимается мусор импортёра. У 460 из 1060 наших памятных `title_original`
   выглядит как «2.000.000 карбованцев, 1995 50 лет ООН AgСеребро 0.925, 33.62g, ø 38.61mm»;
   номинал с годом снимает регулярка, материал — тот же разборщик, что и в миграции `0003`;
2. словарь `app/ukraine_pipeline/lexicon.json` (около 200 пар ru→uk) — единственный способ
   довести «рождения» до «народження»; файл пополняемый, это и есть штатный ответ на
   промах в ревью;
3. сворачивание букв: `і/и/ї/й/ы → и`, `є/е/э/ё → е`, `ґ → г`, мягкий и твёрдый знаки прочь;
4. `rapidfuzz.token_sort_ratio`, плюс два правила: префикс («Ігри ХХХ Олімпіади» против
   «… в Лондоні») и вложенность слов — НБУ называет монету предельно коротко, «Кий» там,
   где у нас «Князь Кий».

Ссылка пишется, если счёт ≥ 88, победитель единственный и монету не занял кто-то другой.
Всё остальное — тай, слабый максимум, занятая монета — уходит в CSV. Две наши записи на
одну монету это дубликат у нас, а не «нашлось лучше»: в CSV колонка `claimedBy` называет
запись, которая монету заняла.

```
--review-out bridge-review.csv     выгрузить кандидатов
--apply-review bridge-review.csv   прочитать решения (столбец decision = yes)
```

Решение из CSV применяется и к позиции, у которой в прогоне кандидатов не было вовсе:
файл `--duplicates-out` шага `gaps` состоит именно из таких пар.

Результат — `price_source_links` по одной строке на источник:
`UA-Coins` и `Wikipedia` — URL страницы монеты, `NBU` — идентификатор карточки
(страницы монеты у НБУ нет, его каталог — один листинг).

**series — наши серии под именами НБУ.** По `app/ukraine_recon/series_map.json`;
английские имена — из английских карточек, сведённых по идентификатору. Что карта не
покрывает, попадает в отчёт, а чинится строкой в JSON. Две наши «серии» серией не являются:
«Государство Украина (1992 - 2026)» — корзина ua-coins под обиходные монеты, «сил» — обрывок
названия. Их снимают с монет и удаляют пустыми; монеты остаются. Шаг идёт **до** `gaps`,
потому что `gaps` создаёт записи уже под каноническими именами.

**gaps — монеты, которые есть у эмитента и нет у нас.** Кластер с карточкой НБУ, который
после `bridge` ни к чему не привязан, становится общей записью (`created_by NULL`):
название, серия, номинал структурой, год, дата ввода, тираж, материал и вид металла,
масса, диаметр, гурт. Одно место — `read_cluster` — превращает кластер в наши колонки,
и тот же код использует `repair-gaps`.

Только монеты. Набор — продукт; ролик обиходных памятных — тоже продукт: его карточка
достаточно называет монету, чтобы её сопоставить, и недостаточно, чтобы её создать
(металла и серии на ней нет). И то и другое считается в отчёте и пропускается.

**Дубликат не создаётся.** Если у нас уже есть непривязанная активная запись того же года
и номинала (и той же серии, когда серию называют обе стороны), запись не создаётся: пара
уходит строкой `would_duplicate` в `--duplicates-out` — в том же формате, что читает
`--apply-review`. Человек ставит `yes`, мост связывает **нашу** запись с этим кластером, и
следующий прогон `gaps` видит кластер занятым и не создаёт ничего. Если пара разная —
связываем нашу запись с её настоящим кластером, и защита перестаёт срабатывать.

**repair-gaps — дозаполнение уже созданных.** Проходит по общим записям с
`source_key LIKE 'nbu:%'`, находит кластер по идентификатору карточки и заполняет то, что
пусто: `denomination_id`, `series_id`, `composition_id`, `metal_kind`, `material`,
`title_en`, дату, тираж, массу, диаметр, гурт. **Только пустое** — исправление человека
важнее карточки. Нужен потому, что первые 96 записей были созданы до того, как разборщик
научился читать «1 грн» и «срібло».

**merge — две наши записи на одну монету, сведённые в одну.** Шаг ничего не решает сам:
он перечисляет пары (запись из `gaps` ↔ наша непривязанная того же года, номинала и серии)
в CSV — со счётом, с описанием из карточки НБУ и со словами, общими у нашего названия и
этого описания. Именно описание различает четыре «Пекторалі» одного года и номинала:
леопард, лев, грифон, людина — в тексте карточки, а не в её названии.
По `--apply-merge` для помеченных `yes`: на выжившую запись переезжает **всё**, что
ссылалось на старую — экземпляры владельцев и их фото, покупки, продажи, предложения,
история цен, ссылки на источники; старая архивируется с причиной `merged into #N` и
удаляется только после того, как на неё ничего не ссылается (порядок из
`04-business-rules.md`, п. 10). Отчёт печатает количества и суммы экземпляров на обеих
записях до и на выжившей после — они обязаны сойтись.

**titles — официальное название.** `title_original` и `title_uk` — формулировка НБУ без
суффикса металла (`(с)`, `(н)`), без «у сувенірному пакованні» и без обрамляющих кавычек;
два маркера встречаются в любом порядке, поэтому снимаются до неподвижности. Латинская
буква внутри кириллического слова («рокiв», «УHР») чинится: это то же слово, и поиск по
«років» должен его находить. `title_en` — с английской карточки, оба `*_source = official`.
Википедия — сверка, а не источник: расхождение уходит в отчёт, а не в базу. Старое русское
название не сохраняется — русского слота нет.

**photos — фото один раз и наши.** Порядок выбора: полноразмерный PNG НБУ (у 389 карточек),
иначе 600 px WebP с ua-coins, иначе превью НБУ 198 px последним средством — 600 больше 198,
и качество здесь важнее порядка предпочтения источников. Оригиналы не хранятся: скачали,
пережали в наши три размера, выбросили. `media_files.source` = `nbu` / `ua_coins`,
`attribution` = «Національний банк України» / «ua-coins.info», `license` — условия
первоисточника. Хотлинки uCoin у украинских записей удаляются: они никогда не скачивались
и показывать их мы не вправе. `--limit N` режет прогон на порции, кэш страниц на диске
означает, что повтор не стоит трафика; отчёт печатает фактический объём по каждому размеру.

**prices — по одному снимку на связанную монету.** `source = 'UA-Coins'`,
`created_by = NULL`, дата — та, что ua-coins печатает над колонкой цены. Проверки — те же,
что в разделе 6; не прошедший снимок пишется с `is_suspect`, а не выбрасывается. Заодно
пересматриваются флаги, поставленные миграцией legacy: тогда у правила отклонения не было
рыночной цены, теперь есть. Суточная задача — этап 5, здесь разовый снимок.

### Отчёт

JSON + сводка в терминал, как у разведки и у миграции. По репетиции на восстановленной
копии боевой базы (2026-09-04): связано 797 (594 по ссылке, 203 по скору), в ревью 160,
без кандидатов 103, создано 237 записей, названий обновлено 784 (782 с английским),
цен записано 780. Боевые числа даст боевой прогон — runbook в `backend/README.md`.

### Права и атрибуция

- НБУ, `/ua/useterms`: материалы сайта могут использоваться **исключительно со ссылкой на
  первоисточник**. Поэтому `attribution` заполняется всегда и показывается под фотографией.
- ua-coins.info: `© Copyright 2015–2026`; их фото берутся только там, где у НБУ нет своего,
  и тоже с подписью.
- Пауза между запросами ≥ 450 мс, честный User-Agent, кэш на диске — чужой сервер не
  должен платить за наши повторные прогоны.

## 10. Обиходные монеты Украины — мини-конвейер (этап 4.5, часть A, п. 1)

~197 несвязанных обиходных позиций Украины: копейки 1/2/5/10/25/50 и гривны
1/2/5/10 (`collection_group = 'circulation'`, `created_by IS NULL`). Раздела 9 они
не касаются — там только памятные. Отдельный конвейер, потому что источники другие
и мост проще: ключ «номинал + год» из таблицы Википедии однозначен сам по себе, без
нечёткого сравнения названий.

### Источники

**Тираж по годам** — украинская Википедия, статья «Монети української гривні»,
раздел «Тиражі та хронологія випуску розмінних та обігових монет»
(`app/ukraine_recon/wikipedia.py:parse_mintage_table`). Одна таблица: строки — годы
1992–2026, столбцы — десять номиналов плюс «Загалом», разобрана как таблица
(rowspan/colspan). Внутри таблицы — строки-разделители монетных дворов
(`<th colspan="12">`), отсеиваются тем, что первая ячейка не парсится как год.
Значение ячейки: «610 млн» / «5 тис**» / «Ні» / «Так***» / «?» — множители
млн=10⁶, тис=10³, шт=1; звёздочки — примечания самой таблицы (* пробные монеты,
** тираж только для коллекционных наборов, *** официально не выпущена,
**** образец 2001 года, ***** образец 2018 года). 2018 год — единственная
ячейка сразу с двумя числами («140 млн***** 20 тис****»): переходный год между
образцами гривны, оба числа реальны.

Единица измерения — свойство самой ячейки, а не общая для колонки или таблицы:
«шапка задаёт множитель на всю колонку» была рабочей гипотезой при разборе
бага ниже, живая страница её не подтвердила — каждая ячейка с числом сама
называет свой множитель («300 шт», не голое «300» под колонкой «в тисячах»).

**Фикс 2026-09-05: 1992 год ломал сумму тиража, а не единицы измерения.**
Живая таблица делит 1992 год на две строки-раздела «монетный двор»:
Istituto Poligrafico e Zecca dello Stato (Италия) и Луганський
верстатобудівний завод — оба чеканили в 1992 году, и для части номиналов
(10, 25, 50 копеек) это два реальных, немалых тиража, а для остальных
(1, 2, 5 копеек, 1 гривня) — итальянский тираж плюс луганская пробная партия
в несколько сотен штук. `parse_mintage_table` честно возвращает обе строки —
две `MintageCell` на один и тот же ключ (номинал, год) — а `circ_mintage.py`
складывал их в `dict`, из-за чего вторая строка молча стирала первую: боевой
прогон записал «1 копійка · 1992» тиражом 300 (луганская пробная партия)
вместо 610 000 300 (итальянский тираж плюс она же). Правка — `usable_count`
в `app/ukraine_pipeline/circ_mintage.py` суммирует все записи без метки
образца по ключу вместо взятия последней; записи с меткой образца (переход
гривны 2018/2001 года) по-прежнему выбираются, не складываются — это две
разные монеты, делящие подпись года, а не два тиража одной. 2018 год —
единственный год с такой меткой; 1992-й — единственный год с двумя строками
монетных дворов. `--circ-refresh-mintage` (`backend/README.md`) пересчитывает
и перезаписывает `mintage_actual` у уже заполненных боевых записей этим
исправлением.

Это уже второй баг с одним корнем — предположение о структуре источника
вместо чтения живой страницы. Первым была карта типов `circ_types.py`:
один тип на 1992–2017 годы, пока проверка `bank.gov.ua/ua/uah/obig-coin`
не показала, что там на самом деле два разных дизайна под одной карточкой
(см. описание типов выше). Вывод общий для обоих случаев — и для карты
типов, и для фикстуры парсера: `tests/test_circulation_pipeline.py` с этого
фикса хранит не придуманную таблицу, а вырезку живой страницы (снята
2026-09-05, URL и дата — в комментарии у фикстуры), потому что придуманная
фикстура ранее не увидела вторую строку 1992 года — то же самое
неведение, тем же способом исправленное.

**Карта типов** (`app/ukraine_pipeline/circ_types.py`) — не придумана, а снята с
официальной страницы bank.gov.ua **«Про монети»** (`/ua/uah/obig-coin/<slug>`,
не тот POST-эндпойнт нумизматического каталога из раздела 3 — там обиходных
монет нет, проверено). Страница без параметров показывает весь стек дизайнов
номинала сразу — каждый как блок `div.hide-show-currency` с заголовком,
статусом («В обігу» / «Поступово вилучається з обігу» / «Вилучена з обігу»),
абзацем «Метка — значение» (дата введения в обращение, металл, диаметр,
толщина, масса, гурт, художник, годы чеканки) и фото аверса/реверса с `alt`,
по тому же принципу, что и в разделе 9. Двенадцать типов: по одному на
каждую копейку 1/2/5/25 (образец 1992, годы 1992–2018 — именно столько
Википедия считает тиражи, дольше официального перечня «годов чеканки», потому
что туда входят и годы, когда чеканили только для коллекционных наборов),
отдельно 10 копеек (1992–2022, фото — текущий, стальной с латунным покрытием
дизайн 2014 года; три сплава под одним номиналом — это уже вариант чеканки,
не тип, остаётся за задачей `catalog_variants`) и 50 копеек (с 1992, чеканится
до сих пор), и шесть гривенных: 1/2/5/10 гривен образца 2018 года (с 2018-го)
и, отдельно от них, 1 гривня — не один тип на весь 1992–2017 диапазон, а два.

**1 гривня 1992–2017 — два типа, не один.** Живая страница «Про монети» для
этого номинала (`100_1996`, тот же адрес и до 2018 года, и после — карточки
старых образцов и образца 2018 стоят на ней стопкой) несёт ровно одну карточку
до 2018 года, заголовок «1 гривня», а её образец фото датирован 2003 годом:
это орнаментный дизайн (тризуб в венке, «Дата введення в обіг» 12.03.1997,
чеканка 1995–2003), не «Володимир Великий» образца 2004 года (постанова
№ 476 від 07.10.2004, масова чеканка 2004–2014, до 2018-го — только для
наборов). Собственный список «Роки карбування» карточки при этом тянется
до 2015 года — Национальный банк не развёл эти два дизайна на две карточки,
хотя они разные. Раньше здесь был один тип на 1992–2017, и все записи
2004–2017 получали то же фото, что и 1992–2003, — чужой дизайн на витрине.
Тип разбит на `hryvnia_1_1992` (1992–2003, подсказка заголовка «1 гривня» —
единственная реальная карточка) и `hryvnia_1_2004` (2004–2017, подсказка
«1 гривня зразка 2004 року» — заголовок, которого на странице нет нарочно):
`circ_nbu.pick_card` для второго типа ничего не находит и тип уходит в
`typesWithoutCard`, вместо того чтобы молча взять фото первого. Отдельной
карточки образца 2004 года на страницах bank.gov.ua нет вообще (проверено
и на `100_1996`, и на `1-grivnya-zrazka-2018-roku` — там стоит та же
единственная карточка образца до 2018 года) — это фиксируемый пробел, не
наша недоработка парсинга; см. `docs/BACKLOG.md`.

### Шаги (`--steps circ-reclassify,circ-bridge,circ-gaps,circ-titles,circ-mintage,circ-photos`)

Переиспользуют `Runner`/`PipelineReport`/`app/ukraine_pipeline/catalog.py`
основного конвейера; порядок и `--apply` — как у части B выше.

**circ-reclassify.** `collection_group = 'circulation'` для Украины исторически
грязная: эвристика `groupFor` (`docs/04-business-rules.md`, п.11 — «гривна ≥ 2 →
памятная, иначе обиходная») отправила сюда и юбилейные обиходные 1 грн
(2004–2016), и карбованцевые памятные 1995–1996 — они не попадают под «гривна
≥ 2», но при этом уже связаны с нумизматическим каталогом НБУ (`source_key
LIKE 'nbu:%'` или строка `price_source_links` с `source='NBU'`). Этот шаг —
первый в порядке — переводит такие активные записи в
`collection_group='commemorative'`, не трогая ничего больше: название, серию
и связи чинит не он. Отдельно (не перенося) считает записи `circulation` с
официальным `title_uk_source='official'`, но без NBU-связи — сигнал для
ручной проверки. Идемпотентен: на втором прогоне запись уже `commemorative`
и больше не кандидат.

Этот счётчик (`officialWithoutNbuLink`) исключает записи, которые
`circ-titles` уже пометил официальным названием сам, честно, без ручной
проверки: запись со связью на статью Википедии в `price_source_links`
(`source='Wikipedia'`) или с `source_key`, начинающимся на `wiki-circ:`
(так помечает свои собственные записи `circ-gaps`). После первого полного
прогона таким становится каждая обиходная монета — без фильтра счётчик
показывал бы все ~190 записей вместо реальных кандидатов на просмотр.

Даже после `circ-reclassify` остальные пять шагов не должны уметь трогать
NBU-связанную запись — на случай, если шаг пропущен в конкретном `--steps`
или новая связанная запись появится в `circulation` позже. Предохранитель —
`OurItem.is_nbu_linked` / `catalog.nbu_linked_ids()`, один и тот же признак
NBU-связи, — исключает такие записи из каждого шага ниже; исключённые
считаются в `skippedNbuLinked`.

**circ-bridge.** Номинал — из структуры (`denomination_id` → `value`/`unit`), а
не из строк названий; у кого не разобран — регуляркой с начала `title_original`
(«25 копеек, 1994») через тот же `app/reference_data/denominations.py`, что и
миграция `0003`, дозаполняет `denomination_id`. Дальше — группировка активных
обиходных записей по (`value`, `unit`, `issue_year`): ключ есть у Википедии и
ровно одна наша запись → связь (`price_source_links`, `Wikipedia`, URL
статьи — одна и та же для всех, страница одна). Ключ есть, наших записей
две и больше (варианты качества чеканки от uCoin) → CSV-ревью (свой формат,
проще, чем у `bridge`: нет кластера и счёта — просто «которая из двух — этот
год и номинал»). Ключа у Википедии нет — запись остаётся непривязанной,
`circ-mintage` просто не найдёт для неё тираж. NBU-связанная запись не
кандидат моста вообще — `skippedNbuLinked` в отчёте, не `withoutWikipediaEntry`.

**circ-gaps.** Для каждого ключа (`value`, `unit`, `year`), где Википедия
подтверждает, что монета существует (не «Ні», не пробная), и ни одна наша
активная запись это место не занимает — новая общая запись:
`collection_group = 'circulation'`, номинал структурой, название и en-название
из `app/ukraine_pipeline/circ_titles.py` (см. ниже), материал/масса/диаметр/гурт
и `subtype` — из карты типов, `source_key = 'wiki-circ:<value>-<unit>:<year>'`
(свой префикс, не пересекается с `nbu:` из раздела 9 и с мостом памятных).
Дубликат не создаётся: если непривязанная наша запись уже стоит в этом году
и номинале — пропуск, а не вторая запись. NBU-связанная запись слот не
занимает: юбилейная 1 грн 2004 года в `circulation` не мешает завести
настоящую обиходную того же года и номинала.

**circ-titles.** Название обиходной монеты — это её номинал, и только он:
«1 копійка», «25 копійок», «1 гривня». Вместо ручной карты словоформ —
`app/reference_data/denominations.py:render_label`, тот же хелпер, что уже
формирует подписи номиналов по всему API (CLDR-склонение: один/мало/много,
дробные формы). `title_en` — тем же хелпером, локаль `en` («1 kopiika», «25
kopiikas», «1 hryvnia»): это стандартная официальная транслитерация, а не
машинный перевод, поэтому оба слота помечены `official`. Правка человека
(`*_source = 'manual'`) не перезаписывается — проверяется по каждому слоту
отдельно. NBU-связанная запись исключена из выборки заранее — иначе шаг
переписал бы официальное название юбилейной монеты на голый номинал.

**circ-mintage.** `mintage_actual` — тираж своего года из таблицы Википедии,
по умолчанию только там, где пусто; расхождение с уже заполненным — строкой в
отчёт, не перезаписывается, пока не передан `--circ-refresh-mintage`
(`backend/README.md`) — тогда пересчитывается и перезаписывается у каждой
не-NBU-связанной записи. `mintage_announced` не трогается — у обиходных монет
Википедия даёт одно число, не пару «оголошений/фактичний». Ключу (номинал,
год) может отвечать больше одной строки таблицы — 1992 год единственный,
поделённый на строки двух монетных дворов (см. врезку про фикс 2026-09-05
выше) — записи всех таких строк складываются. Единственное исключение —
ячейка с меткой образца (гривна, 2018 год: «образец 2018 года» берёт 140 млн,
«образец 1992 года» — 20 тыс) разбирается по `subtype` записи, а не
складывается: это два разных дизайна, делящих подпись года, а не два тиража
одной монеты; запись без `subtype` или без совпавшей метки — в `ambiguous`, не
угадывается. NBU-связанная запись исключена из выборки — иначе тираж обиходной
монеты того же года и номинала влился бы в юбилейную.

**circ-photos.** Фото снимается один раз на тип (не на каждый год): страница
«Про монети» этого номинала, карточка выбирается — без подсказки первая
(самый новый дизайн, для копеек с одним типом) либо точным совпадением
заголовка (для гривны, где на одной странице стоят образец 1992 и образец
2018 сразу — «1 гривня» не подстрока «1 гривня зразка 2018 року», сравнивается
равенством, после нормализации обеих строк — NFC и схлопывание пробелов,
включая неразрывный `\xa0`, — иначе случайный nbsp в заголовке страницы молча
роняет тип в `typesWithoutCard`). Пережимается в наши три размера один раз,
дальше копия на каждую позицию этого типа: `storage_key` несёт
`catalog_item_id`, общего ключа на несколько позиций схема не допускает,
объём — килобайты на позицию, не гигабайты. `media_files.source = 'nbu'`,
`attribution = «Національний банк України»` — это метка поставщика фото со
страницы «Про монети», а не признак связи с нумизматическим каталогом; НЕ то
же самое, что `price_source_links.source = 'NBU'`, по которому исключаются
NBU-связанные записи (`skippedNbuLinked`) ещё до отбора по типу. Хотлинки
uCoin у обиходной части снимаются так же, как в разделе 9.

Идемпотентность («у записи уже есть обе стороны — не трогаем») ломается,
когда меняется сама карта типов: после разбиения 1 гривны (см. выше) все
записи 2004–2017 годов остались с уже сохранённым фото образца 1992 года,
и обычный прогон их не тронул бы, потому что формально у них уже «обе
стороны на месте». `--circ-refresh-types key1,key2` — рычаг на этот случай:
для перечисленных ключей карты типов шаг сначала удаляет уже сохранённые
`nbu`-фото их записей (строки `media_files` и объекты в MinIO), потом
проходит как обычно, так что тип по-настоящему перезапрашивается (или, если
у типа нет карточки — как у `hryvnia_1_2004`, — честно остаётся без фото
вместо чужого). Без опции поведение то же, что раньше. Считается
отдельно — `refreshedItems` в отчёте. Удаление берёт со связанных с типом
записей вообще все `nbu`-фото ролей аверс/реверс, не пытаясь отличить свои
от чужих: запись, которую предлагает `circ-photos`, уже исключена из
NBU-связанных (см. `circ-reclassify` выше), а фото раздела 9 пишется только
на NBU-связанную запись — так что чужому `nbu`-фото здесь взяться неоткуда.

### Известное упрощение

2018 год — единственный, где Википедия несёт два тиража в одной ячейке
(переход образца). `circ-gaps` создаёт только запись образца 2018 года — ключ
«номинал + год» один на пару, второй записи из того же ключа не бывает.
Позиция «1 гривня зразка 1992 року, карбування 2018» (20 тыс штук) сама не
заводится; `circ-mintage` умеет разобрать её тираж, если завести позицию
вручную и проставить `subtype`. Одна строка из ~200 — сознательно не в ущерб
полноте остального.

### Отчёт и результат

Пробный прогон против пустой локальной базы, живые источники (2026-09-04):
таблица Википедии — 350 ячеек; `circ-gaps` создал 168 записей, 1 пропущена
обоснованно (1 копейка 2019 года — по легенде таблицы «офіційно не випущена,
але існує», для неё нет типа в карте, и это правильно: не обиходная монета в
привычном смысле); `circ-titles` и `circ-mintage` — без расхождений (только
что созданные записи уже несут верное название и тираж); `circ-photos` — 11
типов (до разбиения 1 гривны), 336 файлов (168 позиций × 2 стороны), 0
ошибок.

**Боевой прогон против базы владельца, 2026-09-04.** 191 запись получила
название, тираж и фото. Ручное вмешательство по ходу:

- `circ-bridge-review.csv` — из строк с несколькими кандидатами (варианты
  качества чеканки от uCoin на один год и номинал) применено 18 решений
  `yes`; 21 строка сознательно оставлена нерешённой — это и есть задача про
  варианты чеканки (`catalog_variants`), не CSV-ревью моста;
- шесть юбилейных 1 гривня (id 1330–1335) переведены в `commemorative`
  вручную, прямым SQL, в обход `circ-reclassify`: NBU-связи у них нет вообще,
  так что предохранитель `is_nbu_linked` их не видит и не увидит — эвристика
  `groupFor` отправила их в `circulation` по одному лишь номиналу, без каких
  бы то ни было признаков, на которые может опереться автоматика.

Разбиение 1 гривны на `hryvnia_1_1992`/`hryvnia_1_2004` сделано уже после
этого прогона — записи 2004–2017 годов из тех 191 держат фото образца
1992 года (старый баг) до `--circ-refresh-types hryvnia_1_2004` (см. выше).
Ключ для `--circ-refresh-types` — это тип, под который запись группируется
*сейчас*, по новой карте (`hryvnia_1_2004` для 2004–2017), а не тот, под
которым когда-то было записано её фото: `_items_by_type` группирует по
текущей карте типов, старый ключ `hryvnia_1_1992` больше не видит эти годы
вообще. Остаточные хвосты после боевого прогона и разбиения — `docs/BACKLOG.md`.

### Варианты, тройка 2018 года, юбилейные и остаток части B (2026-09-05)

Закрывает пять хвостов выше: 21 нерешённую строку `circ-bridge-review.csv`,
тройку `1 гривня` 2018 года без `subtype`, дубль 1518/1513, шесть юбилейных
1 гривня без NBU-связи, `hryvnia_1_2004` без фото и инвентаризацию остатка
части B. Модель `catalog_variants` / `collection_items.variant_id` уже была
полностью реализована по `02-data-model.md` (миграция `0001`) — миграции в
этой задаче не понадобилось вообще.

**`circ-variants`** (`app/ukraine_pipeline/circ_variants.py`, новый шаг в
`CIRCULATION_STEPS`, сразу после `circ-bridge`). Группирует активные
непривязанные к НБУ обиходные записи по `(номінал, одиниця, рік)`; ключ, где
ровно одна запись уже связана с Вікіпедією (`circ-bridge`), а остальные —
нет, — это ровно случай части 21 строки: непривязанная запись становится
`catalog_variants` к связанной. Подпись варианта берётся **только** из уже
сохранённых в нашей базе данных импорта uCoin — `title_original` (маркеры
«вдавлен»/«тризуб» → `"Втиснутий тризуб"`) или `material` (маркеры
«магнітн»/«немагнітн», перевёрнутые по порядку проверки — «немагнітна»
содержит подстроку «магнітн», так что негативный маркер проверяется первым).
Ничего с живого uCoin не читается. Неразличимая пара уходит в
`--circ-variants-review-out` — CSV со свободным полем `variantName`,
`--apply-circ-variants-review` создаёт вариант по вписанному человеком
названию. Личные экземпляры на записи, которая становится вариантом, не
перевешиваются (архивация, не перепривязка, `04-business-rules.md`, п. 10) —
непустой список считается в `personalInstancesOnVariant`, не блокирует
архивацию. Идемпотентность — через `is_archived` записи-дубля, а не через
уникальный индекс `catalog_variants`: он не ловит повтор, потому что
`mint_mark IS NULL` не считается равным самому себе в уникальном индексе
PostgreSQL.

**Тройка 2018 года и пара 2013 года — тот же шаг, не отдельный код.** Для
номиналов, у которых есть более одного `subtype` в `circ_types.py`
(сегодня — только гривня), `circ-variants` сначала пытается проставить
`subtype` каждой записи слота по её собственным `weight_grams`/`diameter_mm`
против профиля каждого дизайна (допуск ±0.2 — округление uCoin до десятых).
Затем слот перегруппировывается уже по `subtype`: две записи с одним и тем
же `subtype` — настоящий дубль, дальше по общей логике варианта выше; записи
с *разными* `subtype` — два законных разных дизайна, делящих подпись года
(ровно случай тройки 2018 года: старый дизайн, отчеканенный в 2018-м только
для наборов, — не дубль нового образца), и никто из них не архивируется,
только получает `subtype`. Отчёт — `subtypesAssigned`. Если у записи нет
физических полей или профиль не даёт однозначного совпадения — она остаётся
без `subtype` и, если делит слот с чем-то ещё, уходит в тот же CSV-ревью;
не угадывается.

**Фикс: `type_for()` не видел `subtype` (`circ_types.py`).** До этой задачи
тип выбирался только по `(номінал, рік)`. Запись старого дизайна, датированная
2018 годом (тираж для наборов), падала в `hryvnia_1_2018` — единственный тип
с открытым `year_from` — и `circ-photos` молча отдавал бы ей фото нового
образца. `type_for(value, unit, year, subtype=None)` теперь, если `subtype`
передан, сначала ищет точное совпадение `(unit, value, subtype)` по всей
таблице `TYPES`, не глядя на диапазон лет, и только потом — обычный поиск по
году. Старые вызовы без `subtype` не меняют поведения; `circ_photos.py`
теперь читает и передаёт `CatalogItem.subtype` в `type_for`.

**Фикс: `circ_mintage._PATTERN_BY_SUBTYPE` не знал про `SUBTYPE_2004`.**
Таблица Вікіпедії различает только два образца в ячейке 2018 года («зразка
2001 року» / «зразка 2018 року») — она не видит разницы между дизайном 1992
и дизайном 2004 внутри «старого» образца. Запись с `subtype=SUBTYPE_2004` в
2018 году раньше не резолвилась вообще (`ambiguous`) — добавлена строка
`SUBTYPE_2004: PATTERN_2001` в маппинг, рядом с `SUBTYPE_1992`. После неё
`--circ-refresh-mintage` сводит `ambiguous` для тройки 2018 года к нулю.

**`jubilee-bridge`** (`app/ukraine_pipeline/jubilee_bridge.py`, отдельный
шаг, не входит в `CIRCULATION_STEPS`). Точечный поиск по тому же
POST-эндпоинту НБУ (`app/ukraine_recon/nbu.py:search_url`, параметр
`search`, добавлен туда же), по одному запросу на каждую из шести записей
(находятся по форме — `commemorative`, 1 гривня, год из
`THEMES_BY_YEAR`, без NBU-связи, — не по хардкоду id). **Каждый кандидат
всегда уходит в CSV-ревью, автосвязывания нет вообще** — в отличие от
`bridge.py`, здесь нет объёма, который оправдывал бы порог доверия, только
риск тихой ошибочной связи на шести редких записях. Apply пишет **только**
`price_source_links` (`source='NBU'`) — `source_key` не трогается: он несёт
легаси-историю Excel-импорта, а `OurItem.is_nbu_linked` уже видит одну
`price_source_links`-строку как достаточное доказательство связи, так же,
как для записей `bridge.py` (часть B).

Честная находка живой разведки 2026-09-05: поиск по всем шести темам
(«60 років визволення України», «20 років … гривні», «футбол» и т. д.) **не
нашёл ни одной карточки номиналом 1 гривня** ни для одной из шести тем —
совпадения существуют, но на 2/5/10/20/50/100/250 гривень и на смежные, не
точно совпадающие годы и темы (например, «60 років визволення **Києва**»,
5 грн, 2003 — не «України», не 2004). Это может значить, что шесть записей
никогда не были сувенирными продуктами НБУ в современном смысле, либо что
поисковый запрос нужно расширять против реального `title_original` записи, а
не только против темы из этого документа. `THEMES_BY_YEAR` — стартовая точка,
не гарантированное совпадение; пустой или слабый результат — материал для
человека, не повод считать задачу невыполнимой.

**`hryvnia_1_2004` — фото с ua-coins.info, честно не найдено вживую.**
`circ_types.CoinType.ua_coins_id: int | None` — если у типа нет карточки на
«Про монети» **и** задан `ua_coins_id`, `circ-photos` строит URL
`ua_coins.image_url(id, side, "middle_webp")` напрямую (без похода на
страницу, тот же вызов, что `app/ukraine_pipeline/sources.py:ua_coins_sides`
уже делает для части B) и пишет `media_files.source='ua_coins'` с той же
атрибуцией/лицензией, что и часть B (`app/ukraine_pipeline/photos.py`).
Механизм готов и покрыт тестом (`tests/test_circulation_pipeline.py`,
синтетический `ua_coins_id`) — **но реальный id для `hryvnia_1_2004` не
найден живьём, 2026-09-05.** ua-coins.info сам по себе недоступен из среды
разработки (та же проблема, что описана в разделе 4 этого документа), но его
копия в Wayback Machine — доступна, и `catalog/all/all` через неё
действительно прочитан (1060 строк). Строки с точным заголовком «1 гривня»
в этой таблице — не обычная обиходная монета, а памятные выпуски-омонимы
(например, юбилейная «’1 Гривня’» 2021 года из раздела про юбилейные записи
выше); отдельной строки постоянно чеканящейся обиходной 1 гривні в этой
таблице обнаружить не удалось — похоже, `catalog/all/all` покрывает
памятный/сувенирный ассортимент НБУ, а не обиходный оборот. До тех пор
`hryvnia_1_2004` остаётся без фото (`typesWithoutCard`), как и было;
`ua_coins_id` проставляется вручную, как только id найден — например, через
страницу конкретной монеты на ua-coins.info, а не через сводную таблицу.

**`inventory-b`** (`app/ukraine_pipeline/circ_inventory.py`, отдельный шаг).
CSV по всем активным памятным/коллекционным записям без NBU-связи: метал —
по маркерам в `title_original` («золот», «срібн»/«серебр»), до трёх
кандидатов НБУ — тот же `Lexicon.score`/`REVIEW_THRESHOLD`, что `bridge.py`,
против уже закешированного полного обхода `Sources.nbu` (одна и та же сеть,
что уже нужна `bridge`/`series`/`gaps`, не новая нагрузка). Действие: `link`
при найденном кандидате, `archive` при маркере годового набора в названии
(«річний набір», «набір монет», «годовой набор» и т. п.) без кандидата,
иначе `manual`. Строго по требованию задачи — `collection_group` не получил
нового значения под «набор»: раз подходящего enum нет, предложение — архивация
с причиной, а не миграция схемы под одну метку; решение «архивировать как
набор» принимает человек по CSV. Применяется автоматически только `link` —
через ту же пару функций, что `jubilee-bridge` (`jubilee_bridge.
read_review_csv`/`write_links`): формат колонок `decision`/`itemId`/`nbuId`
специально общий у обоих инструментов, один способ применения на двоих.
`archive`/`manual` — не автоматизируются, это админская операция вне
рамок этой задачи.

### Диагностика и `merge-b` (2026-09-05)

Ручная SQL-диагностика того же остатка части B перед запуском `inventory-b`
уточнила прежнюю оценку «~103 позиции без кандидата» и нашла источник
большей части остатка.

**Факты, проверенные вручную:**

- `collection_group` в проде несёт ЧЕТЫРЕ значения — `commemorative` (793),
  `collector` (387), `circulation` (188), `other` (1) — а не два-три, как
  предполагали часть кода и доков ранее: Excel-эвристика легаси-импорта
  клала драгметалльные позиции в `collector`, а не в `commemorative`.
- Несвязанных с НБУ общих украинских записей (`country_id` Украины, группы
  `commemorative`/`collector`/`other`, без `source_key nbu:%` и без NBU-строки
  в `price_source_links`) — **136**, а не ~103.
- **118 из 136 — не пробелы, а дубли**: у каждой есть активная общая запись
  той же страны с тем же `issue_year` и `denomination_id`, уже связанная с
  НБУ. Пример: запись 951 «Петро Могила» (Excel-заголовок «10 гривен, 1996
  400 лет со дня рождения Петра Могили AgСеребро 0.925, 16.94g, ø 33mm»,
  `source_key` от uCoin-импорта) и запись 3185 «Петро Могила» (`nbu:33`,
  созданная `gaps.py`, часть B) — одна и та же монета под двумя заголовками.
  Экземпляры коллекции висят на несвязанных записях всего в 4 случаях из 136.
- Происхождение дублей — легаси-импорт Excel, а не uCoin-импорт пользователя:
  русский заголовок нёс склеенные номинал, год, название и материал одной
  строкой, и `merge.py`'s собственный ключ (тот же `source_key`, который
  `gaps.py` пишет для *своих* дублей) их не видит — они существовали в базе
  задолго до `gaps.py`.
- `is_active` у стран истинно у ТРЁХ строк, не только у Украины — факт,
  документированный в `02-data-model.md` и `BACKLOG.md`, к слиянию не
  относится, код витрины не тронут.

**Почему `bridge.py` (часть B) и `inventory-b` сами не нашли эту пару.** Обе
сравнивают заголовок с *всей* картой НБУ (~1000 карточек) и доверяют
кандидату только при `bridge.REVIEW_THRESHOLD` (55) и выше — порог,
откалиброванный под открытый поиск, где случайное совпадение — реальный
риск. `Lexicon.score` уже срезает материальный хвост и заголовок импортёра
до сравнения (`lexicon.strip_import_noise`), и даже после этого пара Могила
оценивается в 46, пара «Десятинна церква» — в 50: обе ниже общего порога
части B (`test_merge_b.py` проверяет это утверждение напрямую против
`bridge.REVIEW_THRESHOLD`, так что будущая правка любого из чисел — видимая
поломка теста, а не тихий регресс).

**`merge-b`** (`app/ukraine_pipeline/merge_b.py`, новый шаг в `EXTRA_STEPS`,
перед `inventory-b` — каждая слитая пара уменьшает то, что достаётся
`inventory-b`). Сети не требует вовсе — вся работа по уже загруженному
каталогу, без `Sources`. Кандидаты отбираются по ключу (`issue_year`,
`denomination_id`) — коллизионному (у «5 гривень 2018» кандидатов много),
поэтому он только сужает поиск, а не решает; ранжирование — тем же
`Lexicon.score`, что и мост, но по названию сироты, очищенному функцией
`clean_orphan_title` (обёртка над `lexicon.strip_import_noise` с
собственными тестами на паре Могила/Десятинна — без очистки топ-кандидат
не берёт нужный порог ни у одной из пар, `test_merge_b.py`), и сравнивается
и с `title_original` двойника, и с его `title_uk`. Топ-кандидат становится
`suggestedTwinId` только когда явно лидирует над вторым (`SUGGEST_MARGIN`) и
берёт минимальный порог (`CANDIDATE_FLOOR`, ниже открытого порога части B —
слот уже сужен годом и номиналом, случайное совпадение не тот риск); близкий
результат — `suggestedAction=manual`, пустой слот — `no-twin`
(юбилейная шестёрка `jubilee-bridge` и подобные штучные записи без
карточки НБУ вообще падают именно сюда).

CSV — одна строка на сироту (`decision`, `orphanId`, `orphanTitle`,
`cleanedTitle`, `instanceCount`, до трёх `candidates` вида
`id:title:score`, `suggestedTwinId`, `suggestedAction`). Автослияния нет
даже при явном лидере — это разовая чистка легаси-остатка, не постоянный
шаг конвейера. `--apply-merge-b` читает только строки `yes` с непустым
`suggestedTwinId` и передаёт пары напрямую в уже существующий
`merge.apply_merges`: перенос экземпляров, личных снимков цены (общие у
двойника уже есть) и фото, архивация сироты причиной `merged into #<id>`,
удаление только после того, как на неё ничего больше не ссылается
(`04-business-rules.md`, п. 10) — тот же порядок, что `merge.py` и так
соблюдает для дублей, которые создаёт сам `gaps.py`. `source_key` сироты не
трогается — это легаси-история импорта. Идемпотентно: повторный `--apply`
того же файла ничего не меняет, потому что запись уже удалена первым
проходом.

## 11. LLM-переводы украинского остатка (этап 4.5, часть C)

Всё, что предыдущие шаги части B/A могли назвать от лица эмитента, уже носит
`*_source = 'official'` (`titles.py`, `circ_titles.py`, `series.py`). Что
осталось после `merge-b` и инвентаризации — легаси-записи без карточки НБУ
вообще: русские заголовки Excel-импорта («Енеїда» ×9, держсимволи ×6,
банкноти, «Архістратиги», східний календар и подобные, ~80 штук), шесть
юбилейних 1 гривень (id 1330–1335, `jubilee-bridge` не нашёл карточки живьём)
и отдельные пробелы `title_en` у уже связанных записей и серий. Для них
источника нет — их называет модель, и это единственное место в конвейере,
где перевод не от эмитента; помечается это честно `*_source = 'llm'`, а не
`'official'`.

Часть, которую эта задача **не** делает: полный охват «часть C» из
`11-roadmap.md` (весь СССР, США, страны и серии без CLDR-названия) — только
украинский остаток общего каталога. Остальное — `docs/BACKLOG.md`.

### Шаг `translate-c`

`app/ukraine_pipeline/translate_c.py`, отдельный шаг в конце `STEPS`
(`runner.py`) — сети НБУ/ua-coins/Wikipedia не требует вовсе, только
`api.anthropic.com`. Модель — константа в коде (`translate_c.MODEL`,
`claude-haiku-4-5`): перевод коротких каталожных названий не требует
дорогой модели.

**Выборка** — идемпотентная по конструкции: общая (`created_by IS NULL`)
украинская запись попадает в неё, если `title_uk` пуст ИЛИ
`title_uk_source = 'llm'`, и/или то же самое для `title_en` — независимо
друг от друга, так что запись с официальным `title_uk`, но без `title_en`,
получает только английское название. `official` и `manual` никогда не
переоцениваются. Серии — тем же правилом, но только для `name_en` (у
`coin_series` уже есть `name_en_source` с миграции `0003`, отдельной
миграции для провенанса не понадобилось); `name_uk` серий этот шаг не
трогает.

**Батчи и провенанс.** ~20 записей на один запрос модели, JSON-in/JSON-out
через принудительный вызов инструмента (`tool_choice`) со строгой схемой —
это, а не свободный текст, и есть тот самый «строгий разбор»: ответ либо
проходит `_validate_batch` (каждый id из батча присутствует, у каждого
нужного слота непустая строка), либо весь батч уходит на один повтор, а
после второй неудачи — в отчёт `errors` без применения. Промпт просит
каноническую украинскую формулировку в стиле самого НБУ («Різдво Христове»,
не «Різдво (монета)») и английскую в стиле англоязычного каталога НБУ; год,
метал, масса и диаметр в названии не повторяются — они уже в своих колонках.
Всё записанное помечается `*_source = 'llm'`.

**`title_original` для украинского оригинала.** Модель `title_{сущность}_original`
— язык эмитента; для Украины это украинский (`02-data-model.md`). Запись, чей
`original_lang` не `'uk'` (легаси-русский Excel-заголовок), при генерации
`title_uk` получает `title_original := сгенерированный title_uk` и
`original_lang := 'uk'`; исходная русская строка после этого нигде в базе не
остаётся — только в CSV-отчёте (`id`, старый original, старый язык, новые
uk/en). Запись, у которой `original_lang` уже `'uk'`, не трогается, даже если
`title_uk` пришлось перевести заново.

**`--dry-run` не ходит в сеть вовсе** — единственный шаг конвейера, который
тратит деньги за прогон, поэтому по умолчанию dry run показывает только
выборку и план батчей (`plannedItems`, `plannedSeries` в отчёте) и
останавливается. Исключение — `--translate-out FILE`: даже без `--apply` он
вызывает модель и пишет CSV для ревью (`newUk`/`newEn` реальные, не
плейсхолдер), но в базу по-прежнему ничего не пишет. `--apply` не читает
CSV построчно (там нет колонки `decision`, как у `bridge`/`merge`) — он
просто пересчитывает те же батчи и пишет результат; построчное ревью здесь
избыточно, потому что провенанс `llm` и так помечает каждую строку как
подлежащую проверке при следующем взгляде на запись.

Runbook (`backend/README.md`): `ANTHROPIC_API_KEY` — обязательная переменная
окружения для `--apply`/`--translate-out` (у самого `--dry-run` она не
нужна), ключа в репозитории нет и не будет. Пример:

```bash
docker compose run --rm -v "$PWD/migration-reports:/reports" \
  api python scripts/ukraine_pipeline.py \
    --steps translate-c --translate-out /reports/translate-c.csv \
    --report /reports/translate-c.json --cache-dir /reports/ukraine-cache
```

Отчёт CSV (utf-8-sig, чтобы Excel сразу показал кириллицу) — единственное
место, где остаётся исходная русская строка; после ревью:

```bash
docker compose run --rm -v "$PWD/migration-reports:/reports" \
  api python scripts/ukraine_pipeline.py --apply --steps translate-c \
    --report /reports/translate-c-2.json --cache-dir /reports/ukraine-cache
```

### Admin-правка названий

Отдельного шага конвейера не заводили — правку одной записи вручную делает
человек через API, не батч-скрипт. `PATCH /catalog/{id}` (уже существовавший
эндпоинт CRUD каталога) для `titleUk`/`titleEn` теперь всегда ставит
`*_source = 'manual'` и отклоняет пустую строку `422`-м; `titleOriginal`
правится тем же запросом без пометки источника. Права те же, что и у любого
PATCH общей записи — только admin (`03-api-contract.md`, раздел «Правка
названий»). Экрана в admin-режиме карточки ещё нет — контракт готов,
пункт для фронтенда — `docs/BACKLOG.md`.
