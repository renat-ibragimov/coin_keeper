# 11. Порядок работ

Этапы упорядочены так, чтобы каждый заканчивался **проверяемым результатом**, а не
«написали слой». Следующий этап не начинается, пока не выполнен критерий приёмки предыдущего.

**Текущее состояние: этап 0 завершён. Следующий — этап 1.**

---

## Этап 1. Каркас бэкенда

- Структура проекта FastAPI, конфигурация через переменные окружения
- `docker-compose.yml`: postgres, redis, minio, api
- SQLAlchemy-модели по `02-data-model.md`
- Первая миграция Alembic — вся схема целиком
- Аутентификация: регистрация, вход, refresh, `/auth/me` (`07-auth.md`)
- `GET /health`
- pytest + фикстуры с тестовой базой

**Критерий приёмки:** `docker compose up` поднимает окружение, `alembic upgrade head`
создаёт схему, пользователь регистрируется и получает токен, тесты проходят.

## Этап 2. Перенос данных

- Скрипт `migrate_legacy.py` по `09-data-migration.md`
- Загрузка 839 уцелевших изображений в MinIO с превью
- Разделение `storage_key` / `external_url`
- Валидация цен, пометка `is_suspect`
- Отчёт о миграции

**Критерий приёмки:** все проверки из чек-листа `09-data-migration.md` пройдены,
сумма расходов совпадает до копейки — 42 765,66 грн.

## Этап 3. API каталога и коллекции

- `GET /catalog` со всеми фильтрами, сортировкой и постраничной выдачей
- `GET /catalog/{id}` — карточка
- CRUD каталога с правилами доступа (`07-auth.md`)
- CRUD коллекции с автосозданием расхода и подстановкой курса НБУ
- `GET /series`, `GET /series/{id}/summary`
- `GET /bootstrap` со всеми показателями дашборда
- Полнотекстовый поиск

**Критерий приёмки:** через API видны 3063 позиции с фильтрами, 620 экземпляров владельца,
дашборд отдаёт корректные суммы, тесты на расчёт комплектности и финансов проходят.

## Этап 4. Фронтенд, первая версия

- Vite + React + TypeScript + TanStack Query, маршрутизация
- Вход и регистрация
- Каталог: таблица, фильтры, поиск, пагинация, виртуализация
- Карточка монеты с фотографиями
- Коллекция: список, добавление и редактирование покупки
- Дашборд

**Критерий приёмки:** владелец открывает сайт с телефона, находит монету, добавляет покупку,
видит корректные суммы на дашборде.

## Этап 5. Курсы, цены, фоновые задачи

- Воркер ARQ, инфраструктура задач и `GET /jobs/{jobId}` с отменой
- Интеграция с НБУ: ежедневное обновление, догрузка исторических курсов диапазоном
- UA-Coins: обновление цены позиции
- **Слой валидации цен** (`05-integrations.md`) — до записи в базу
- Массовое обновление цен по фильтру с прогрессом и остановкой
- История цен графиком в карточке

**Критерий приёмки:** цена обновляется по кнопке и пакетно, заведомо ломаная цена
отклоняется со статусом `rejected` и попадает в лог, а не в базу.

## После MVP

Приоритет определяется по мере использования:

| Задача | Условие |
|---|---|
| Подтверждение email, восстановление пароля | перед открытием регистрации |
| Продажи (`sales`) | если появится потребность |
| Цели коллекционирования | если появится потребность |
| Предложения о покупке | если появится потребность |
| Разновидности | сначала решить, нужны ли вообще |
| Numista | только с пользовательским API-ключом |
| Мобильные приложения (React Native / Expo) | после стабилизации API |

## Как вести работу

Одна задача — один этап или его часть. Перед началом читать документ, который её описывает:
ссылки указаны в каждом этапе. Отклонения от документации допустимы, но документ тогда
обновляется в том же изменении — расхождение между `docs/` и кодом хуже, чем отсутствие
документа.
