# 11. Порядок работ

Этапы упорядочены так, чтобы каждый заканчивался **проверяемым результатом**, а не
«написали слой». Следующий этап не начинается, пока не выполнен критерий приёмки предыдущего.

**Текущее состояние: этап 0 завершён. Следующий — этап 1.**

## Этап 1. Каркас бэкенда

- Структура проекта FastAPI, конфигурация через переменные окружения
- `docker-compose.yml`: postgres, redis, minio, api
- SQLAlchemy-модели по `02-data-model.md`
- Первая миграция Alembic — вся схема целиком
- Аутентификация: регистрация, вход, refresh (cookie), выход, `/auth/me` (`07-auth.md`)
- **Подтверждение email**: `auth_tokens`, `/auth/verify-email`, `/auth/resend-verification`,
  неактивный аккаунт до перехода по ссылке
- **Восстановление пароля**: `/auth/forgot-password`, `/auth/reset-password`
- **Отправка почты**: внешний SMTP (Resend или Postmark), `SMTP_*` в конфиге, шаблоны двух
  писем (`10-infra.md`)
- **Ограничение частоты** на Redis по таблице лимитов из `07-auth.md` + honeypot-поле
  в регистрации
- `GET /health`
- pytest + фикстуры с тестовой базой

**Критерий приёмки:** `docker compose up` поднимает окружение, `alembic upgrade head`
создаёт схему; новый пользователь регистрируется сам, получает письмо, подтверждает адрес и
получает токен; до подтверждения войти нельзя; восстановление пароля проходит целиком;
превышение лимита попыток входа отбивается `429`; тесты проходят.

## Этап 3. API каталога и коллекции

- `GET /catalog` со всеми фильтрами, сортировкой и постраничной выдачей
- `GET /catalog/{id}` — карточка
- **Фильтр видимости каталога в репозиторийном слое** (`created_by IS NULL OR created_by =
  :user_id`), рядом с фильтром `owner_id`
- CRUD **личных** позиций каталога; общий каталог только на чтение, правка — по роли admin
  (`07-auth.md`)
- CRUD коллекции с автосозданием расхода и подстановкой курса НБУ; удаление экземпляра
  удаляет расход `coin_purchase` в сервисном слое
- Сортировки-агрегаты `owned | purchase | price` через `LATERAL`, а не постобработкой
- `GET /series`, `GET /series/{id}/summary`
- `GET /bootstrap` со всеми показателями дашборда
- Полнотекстовый поиск с учётом `title_uk`

**Критерий приёмки:** через API видны 3063 общие позиции с фильтрами, 620 экземпляров
владельца, дашборд отдаёт корректные суммы; личная позиция второго пользователя не видна
первому, попытка изменить общую запись даёт `403`; удаление экземпляра уменьшает сумму
расходов; тесты на расчёт комплектности, финансов и изоляцию данных проходят.

## Этап 4. Фронтенд, первая версия

- Vite + React + TypeScript + TanStack Query, маршрутизация
- Вход, регистрация с honeypot, «проверьте почту», подтверждение адреса, восстановление
  пароля (`08-ui-map.md`)
- Каталог: таблица, фильтры, поиск, пагинация, виртуализация, пометка «моя позиция»
  и фильтр видов
- Пустой результат ведёт к созданию личной позиции или импорту, а не в тупик
- Создание и правка личной позиции каталога
- Карточка монеты с фотографиями; у общей позиции нет кнопок правки
- Коллекция: список, добавление и редактирование покупки
- Дашборд
- Адаптивность, тёмная тема
- **Локализация: английский и украинский.** Английские строки берём из
  `legacy/ui-strings.json`; **украинские пишем заново** — в бандле их нет, там русские и
  английские (`08-ui-map.md`). Это отдельная задача этапа, а не побочный эффект вёрстки

**Критерий приёмки:** новый пользователь регистрируется с телефона, подтверждает адрес,
находит монету, добавляет покупку, заводит личную позицию для того, чего нет в каталоге,
видит корректные суммы на дашборде; интерфейс полностью переведён на украинский и
английский, непереведённых строк нет.

## Этап 5. Курсы, цены, фоновые задачи

- Воркер ARQ, инфраструктура задач и `GET /jobs/{jobId}` с отменой
- Интеграция с НБУ: ежедневное обновление, догрузка исторических курсов диапазоном
- UA-Coins: разбор страницы и цены позиции
- **Центральная суточная задача `prices-daily-sync`**: обход общего каталога по UA-Coins
  порциями, снимки с `created_by = NULL`, видимы всем (`04-business-rules.md`, п. 7)
- Пользовательское обновление цен **личных** позиций: одной монеты и пачкой, с прогрессом
  и остановкой; снимки с `created_by` = пользователь
- Ручной ввод цены (`POST /prices/manual`)
- Фильтр видимости снимков в выборках и в расчёте стоимости коллекции
- **Слой валидации цен** (`05-integrations.md`) — до записи в базу, на всех путях
- История цен графиком в карточке, с отметкой своих снимков

**Критерий приёмки:** суточная задача проходит по украинской части общего каталога и
обновляет цены без участия пользователя; владелец обновляет цену своей личной позиции по
кнопке и пакетно; попытка обновить цену общей позиции даёт `403`; чужие пользовательские
снимки не влияют на оценку коллекции; заведомо ломаная цена отклоняется со статусом
`rejected` и попадает в лог, а не в базу.

## Этап 6. Импорт, каталог НБУ, экспорт

- Импорт Excel-выгрузки uCoin с двухступенчатой дедупликацией и отчётом
  (`04-business-rules.md`, п. 3): совпало с общим каталогом — привязываем, не совпало —
  создаём **личную** позицию
- **Задача `nbu-catalog-sync`**: еженедельный обход официального каталога нумизматической
  продукции НБУ, сопоставление по «номинал + год + название», обогащение по `COALESCE`
  (`title_uk`, официальные фото аверса и реверса, тираж, характеристики), новые выпуски —
  как системные записи (`05-integrations.md`, раздел 3)
- Экспорт коллекции и текущего фильтра в Excel
- Загрузка своих фотографий с обработкой, `source = 'user_upload'`
- Фоновая загрузка 2796 изображений по `external_url`; скачанные uCoin-файлы наследуют
  `source = 'ucoin'` и его правило видимости (`06-media-storage.md`)
- Скрейпинг uCoin через Playwright — только по запросу пользователя, только в личные позиции

**Критерий приёмки:** повторный импорт той же выгрузки не создаёт дублей и не трогает общий
каталог; задача по каталогу НБУ заполняет `title_uk` и заменяет uCoin-фото украинских
выпусков официальными, новый выпуск с сайта НБУ появляется в общем каталоге сам;
экспорт открывается в Excel.

## Этап 7. Деплой

- Развернуть на Hetzner по `10-infra.md`
- Домен, HTTPS, Caddy
- Боевой SMTP: SPF, DKIM, DMARC для домена, письма доходят не в спам
- Регистрация открыта (`ALLOW_REGISTRATION=true`), расписание системных задач включено
- Бэкапы настроены и **проверены восстановлением**
- PWA: манифест, иконки, установка на телефон

**Критерий приёмки:** сайт доступен по домену, владелец пользуется им с телефона как
основным инструментом; **посторонний человек регистрируется сам**, получает письмо,
подтверждает адрес и заводит свою коллекцию; чек-лист первого деплоя из `10-infra.md`
пройден целиком.

## После MVP

Приоритет определяется по мере использования:

| Задача | Условие |
|---|---|
| «Повышение» личной позиции в общий каталог админом | когда станет видно, что за позиции заводят пользователи и какие из них стоит сделать общими |
| Продажи (`sales`) | если появится потребность |
| Цели коллекционирования | если появится потребность |
| Предложения о покупке | если появится потребность |
| Разновидности | сначала решить, нужны ли вообще |
| Numista | только с пользовательским API-ключом; закрыл бы цены США и СССР |
| OAuth (Google), 2FA | по желанию |
| Мобильные приложения (React Native / Expo) | после стабилизации API |

## Как вести работу

Одна задача — один этап или его часть. Перед началом читать документ, который её описывает:
ссылки указаны в каждом этапе. Отклонения от документации допустимы, но документ тогда
обновляется в том же изменении — расхождение между `docs/` и кодом хуже, чем отсутствие
документа.
