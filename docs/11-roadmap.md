# 11. Порядок работ

Этапы упорядочены так, чтобы каждый заканчивался **проверяемым результатом**, а не
«написали слой». Следующий этап не начинается, пока не выполнен критерий приёмки предыдущего.

**Текущее состояние (2026-09-03): этапы 0–4 завершены. API и статика фронтенда
выкатываются на `coins.renat-ibragimov.com` пушем в `main`. Следующий блок — этап 4.5
«Украинский конвейер» (фото, `title_uk`, цены для украинской части каталога); веха
«Демо» — после него, по решению владельца.**

Правило ведения: каждая завершённая часть этапа обновляет этот документ и затронутые
доки тем же набором коммитов (`CLAUDE.md`, «Правила работы с кодом»).

Чек-лист первого деплоя из `10-infra.md` пройден целиком.

Этап заканчивается работающим контуром: код из `main` живёт на домене, а не на ноутбуке.
Дальше каждый следующий этап выкатывается тем же способом, и «у меня локально работает»
перестаёт быть валютой.

Обязательный тест на каскады: **удаление пользователя, имеющего личные позиции каталога и
экземпляры на них, проходит одним стейтментом и не оставляет осиротевших строк.** Это проверка
каскадного ромба `users → collection_items` и `users → catalog_items` — заодно с тем, что
общий каталог при удалении пользователя не страдает. Второй тест рядом проверяет, что
внешний ключ по-прежнему не даёт оставить экземпляр без позиции каталога
(`02-data-model.md`, «Почему `NO ACTION`, а не `RESTRICT`»).

  «серия × источник», сопоставление по стратегиям A/B/C/C1, кандидаты на добавление,
  фото, цены, названия, права. Итоги и исправленные предположения —
  `05-integrations.md`, раздел 8; runbook — `backend/README.md`. Главные находки:
  каталог НБУ отдаётся одним POST по 100 карточек со всеми полями и фото 1600 px;
  ua-coins.info не отвечает из-за пределов Украины (разведка идёт по копии Wayback,
  доступность с Hetzner — первый вопрос боевого прогона); русская локаль ua-coins даёт
  ключ к нашим русским названиям; по годам 1995–2018 три источника сходятся один в один.
  Боевой прогон против базы — за владельцем.
- [x] **Часть B — модель и конвейер (2026-09-04).** Две половины.

  **Трёхъязычная модель каталога** (миграция `0003`, `02-data-model.md`): у каждой
  именованной сущности — страны, серии, монеты — `*_original` на языке эмитента плюс
  `original_lang`, и два перевода со своим `*_source`. Русский перестал быть языком:
  колонки `title_ru` / `name_ru` / `label_ru` удалены, для СССР русский — это оригинал.
  Заодно перестало быть прозой то, что прозой быть не должно: страны засеяны все 260
  эмитентов (ISO 3166-1 из CLDR + исторические), номинал разобран в `value` + `unit` +
  `currency_code` с подписью по локали, материал — в справочник `materials` плюс масса и
  диаметр. Ответы API идут в локали запроса (`?locale=` / `Accept-Language`).

  **Конвейер** (`scripts/ukraine_pipeline.py`, `05-integrations.md`, раздел 9): шаги
  `bridge → series → gaps → repair-gaps → merge → titles → photos → prices`, каждый
  идемпотентен и ничего не пишет без `--apply`. `bridge` сопоставляет наши записи с
  монетами через словарь ru↔uk и сворачивание букв; спорное уходит в CSV на ревью
  человеку. Фото — один раз в свой MinIO, в трёх размерах (300/600/1200, WebP q80,
  миграция `0004`), первоисточник НБУ, где у него полноразмерного фото нет —
  ua-coins 600 px; хотлинки uCoin у украинских записей вычищены. Репетиция на копии
  боевой базы: связано 797, в ревью 160, создано 237, названий 784, цен 780. Боевой
  прогон — по runbook в `backend/README.md`, за владельцем.
- [x] **Часть B, второй прогон — четыре дефекта моста и `gaps` (2026-09-04).**
  По `bridge-review-2.csv`: 42 из 62 позиций ревью оказались записями, которые `gaps`
  же и создал. Найдено и починено:

  1. `gaps` создавал записи без номинала, вида металла и части серий — НБУ пишет
     «1 грн» и «срібло», а разборщики знали только «1 гривня» и русские названия
     сплавов. Чтение кластера в наши колонки собрано в одно место (`read_cluster`);
     для уже созданных 96 записей — шаг `repair-gaps`, дозаполняющий по `source_key`
     **только пустые** колонки.
  2. `bridge` считал ссылкой только ua-coins, поэтому запись с `source_key = 'nbu:<id>'`
     сравнивалась по названию с нашей одноимённой. Теперь ссылкой считается ключ любого
     из трёх источников, и решение из CSV применяется в том числе к позиции, у которой
     кандидатов не было вовсе.
  3. `gaps` не создаёт запись, если у нас уже есть непривязанная того же года и

## ◆ Контрольная точка: демо владельцу коллекции

Не этап, а веха между этапами 4 и 5. Изначально планировалась сразу после части 3 этапа 4;
**по решению владельца перенесена после украинского конвейера (этап 4.5)** — показывать
имеет смысл с настоящими фотографиями. Ничего не разрабатывается — приложение показывается
живым людям, и по итогам пересматриваются приоритеты этапов 5–6.

К этому моменту работает всё, что нужно для настоящей работы с коллекцией: каталог,
коллекция, покупки, деньги, серии, личные позиции. Не работает автоматика цен и импорт —
именно про них и нужно понять, что важнее.

**Что показываем:**

- **Владелец коллекции** входит под своим аккаунтом и видит **свою** коллекцию: 620
  экземпляров, реальные суммы, свои фотографии. Не демо-данные — его настоящая база,
  перенесённая в этапе 2.
- **Второй администратор** проходит путь нового пользователя целиком и на глазах:
  регистрация → письмо → верификация → вход → пустой дашборд. Пустое состояние — часть
  демонстрации, а не то, что прячут: именно его увидит каждый новый человек.

**Что собираем:** замечания и идеи, без немедленной реализации. Всё записывается, потом
раскладывается по этапам 5–6 и разделу «После MVP». Демо — источник приоритетов, а не
очередь задач на завтра.

**Правило до демо:** в этапах 1–4 ничего из этапов 5–6 не реализуется наперёд. Соблазн
«раз уж я здесь, добавлю кнопку обновления цены» надо гасить: смысл вехи в том, чтобы
приоритеты определялись увиденным, а не тем, что успели написать заранее. Заготовки под
будущее в схеме — можно и нужно (это уже заложено); работающая функциональность — нет.

## Этап 5. Курсы, цены, фоновые задачи

- Воркер ARQ, инфраструктура задач и `GET /jobs/{jobId}` с отменой
- Интеграция с НБУ: ежедневное обновление, догрузка исторических курсов диапазоном
- UA-Coins: разбор страницы и цены позиции
- **Центральная суточная задача `prices-daily-sync`**: обход общего каталога по UA-Coins
  порциями, снимки с `created_by = NULL`, видимы всем (`04-business-rules.md`, п. 7)
- Пользовательское обновление цен **личных** позиций: одной монеты и пачкой, с прогрессом
  и остановкой; снимки с `created_by` = пользователь
- Ручной ввод цены (`POST /prices/manual`)
- Фильтр видимости снимков в выборках и в расчёте стоимости коллекции
- **Слой валидации цен** (`05-integrations.md`) — до записи в базу, на всех путях
- История цен графиком в карточке, с отметкой своих снимков

**Критерий приёмки:** суточная задача проходит по украинской части общего каталога и
обновляет цены без участия пользователя; владелец обновляет цену своей личной позиции по
кнопке и пакетно; попытка обновить цену общей позиции даёт `403`; чужие пользовательские
снимки не влияют на оценку коллекции; заведомо ломаная цена отклоняется со статусом
`rejected` и попадает в лог, а не в базу.

## Этап 6. Импорт, каталог НБУ, экспорт

- Импорт Excel-выгрузки uCoin с двухступенчатой дедупликацией и отчётом
  (`04-business-rules.md`, п. 3): совпало с общим каталогом — привязываем, не совпало —
  создаём **личную** позицию
- **Задача `nbu-catalog-sync`**: еженедельный обход официального каталога нумизматической
  продукции НБУ, сопоставление по «номинал + год + название», обогащение по `COALESCE`
  (`title_uk`, официальные фото аверса и реверса, тираж, характеристики), новые выпуски —
  как системные записи (`05-integrations.md`, раздел 3). Задача **никогда не удаляет**:
  снятое с выпуска архивируется с причиной, вероятные дубликаты уходят в отчёт для ручного
  решения
- Экспорт коллекции и текущего фильтра в Excel
- Загрузка своих фотографий с обработкой, `source = 'user_upload'`
- Фоновая загрузка 2796 изображений по `external_url`; скачанные uCoin-файлы наследуют
  `source = 'ucoin'` и его правило видимости (`06-media-storage.md`)
- Скрейпинг uCoin через Playwright — только по запросу пользователя, только в личные позиции

**Критерий приёмки:** повторный импорт той же выгрузки не создаёт дублей и не трогает общий
каталог; задача по каталогу НБУ заполняет `title_uk` и заменяет uCoin-фото украинских
выпусков официальными, новый выпуск с сайта НБУ появляется в общем каталоге сам, а исчезнувший
из источника архивируется, а не удаляется; отчёт задачи содержит список архивированного
и кандидатов в дубликаты.

## Этап 7. Продакшн-закалка

Сервер, домен, HTTPS и автоматическая выкладка работают с этапа 1 — здесь не разворачивание,
а доведение до состояния, в котором систему не страшно оставить без присмотра.

- **Бэкапы**: база по расписанию, синхронизация MinIO на внешнее хранилище, ротация
- **Проверка восстановления**: бэкап развёрнут в отдельную базу и сверён по количеству
  записей. Бэкап, который ни разу не разворачивали, — не бэкап
- **PWA**: манифест, иконки, установка на домашний экран
- Расписание системных задач включено, задачи отработали хотя бы раз на боевых данных
- **Финальный чек-лист безопасности**: firewall, SSH по ключу, закрытые наружу порты
  Postgres/Redis/MinIO, CORS только на домен фронтенда, отсутствие секретов в логах,
  автоматические обновления безопасности (`10-infra.md`)

**Критерий приёмки:** чек-лист продакшн-закалки из `10-infra.md` пройден целиком; бэкап
восстановлен и сверён; владелец пользуется приложением с телефона как основным
инструментом; **посторонний человек регистрируется сам**, получает письмо, подтверждает
адрес и заводит свою коллекцию.
