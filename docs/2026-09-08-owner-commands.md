# Команды владельца — «Ми сильні» + упаковочный проход по фото (2026-09-08)

Код и тесты обоих блоков — в `main`. К боевой базе сессия ничего не
применяла. Ниже — последовательность ручных прогонов, каждый в своём
докер-контейнере, со стоп-точками между ними: не переходить к следующему
шагу, не посмотрев отчёт/CSV предыдущего.

Подробности каждого шага — `backend/README.md` (по-английски, как весь
код): раздел 9b «roll-series» и раздел «Coin photo packaging scan». Здесь —
только последовательность и что смотреть между прогонами.

## Блок 1. Три недостающие области «Ми сильні. Ми разом»

### Честный итог разведки

`circ-bridge`/`circ-gaps` тут ни при чём — это другой конвейер: обычные
номиналы (копейки, гривны) по таблице тиражей Википедии, «обігові
пам'ятні» его вообще не касаются (`docs/05-integrations.md`, раздел 10).
«Ми сильні» читаются с карточки **ролика** в конвейере части B (раздел 9).
Но шаг `gaps` этого конвейера **никогда** не заводит запись из ролика —
защита в коде (`is_roll_derived`, `app/ukraine_pipeline/gaps.py`): на
карточке ролика нет ни металла, ни серии, а выдумывать их значило бы
нарушить собственное правило проекта «источники не создают record без
подтверждённых полей». Это не пробел, который сессия могла бы починить —
это осознанная защита, оставленная как есть.

Итог: три новые области (Запорізька, Дніпропетровська, Кіровоградська) ни
один существующий автоматический шаг не заведёт — как и девять уже
существующих, это ручной ввод.

### Шаг 1 (dry-run) — посмотреть, что источник уже отдал

```bash
docker compose run --rm -v "$PWD/migration-reports:/reports" \
  api python scripts/ukraine_pipeline.py --dry-run \
    --steps bridge,series,gaps \
    --report /reports/mi-silni-1-dry.json --cache-dir /reports/ukraine-cache
```

Открыть `/reports/mi-silni-1-dry.json` → `details.gaps.skippedRoll` — это
новый список (добавлен этой сессией): заголовок и год каждого ролика,
который источник отдал, но не создал. Если там есть Запорізька,
Дніпропетровська или Кіровоградська 2026-го года — НБУ уже опубликовал
карточки роликов для них. Если нет — ещё не опубликовал, заводить пока
нечего (можно повторить этот шаг позже).

**СТОП-ТОЧКА.** Дальше — только если решили завести новые записи сейчас.

### Шаг 2 — завести записи руками

Не автоматизировано (см. «честный итог» выше) — так же, как в своё время
были заведены девять существующих. Самый безопасный способ — не
выдумывать физические поля (материал, масса, диаметр, гурт), а скопировать
их с любой из уже существующих записей `Ми сильні. Ми разом.%` (монета
физически одна и та же для всех областей, отличается только дизайн и
название): взять `INSERT` по образцу существующей строки
`catalog_items`, поменять только `title_original`/`title_uk`/`title_en`,
`issue_year` и `source_key` (свой, не пересекающийся с `nbu:`/`wiki-circ:`
— например `manual:mi-silni-<область>`). `series_id` можно оставить
`NULL` — его проставит шаг 3.

**СТОП-ТОЧКА.** После того как все нужные записи заведены.

### Шаг 3 — привязать серию (новый шаг `roll-series`)

```bash
docker compose run --rm -v "$PWD/migration-reports:/reports" \
  api python scripts/ukraine_pipeline.py --apply --steps roll-series \
    --report /reports/mi-silni-3-series.json
```

Копирует `series_id` с любой уже привязанной записи `Ми сильні. Ми
разом.%` на записи с `series_id IS NULL` — включая только что заведённые
в шаге 2. Идемпотентен: второй прогон ничего не меняет
(`updated: 0`). Если в отчёте `seriesId: null` — ни у одной из
существующих девяти ещё нет `series_id`; это стоит проверить руками,
такого быть не должно.

## Блок 2. Упаковочный проход по фото

### Шаг 4 (dry-run) — скан существующих фото

```bash
docker compose run --rm -v "$PWD/migration-reports:/reports" \
  api python scripts/scan_coin_photo_packaging.py --dry-run \
    --out /reports/coin-photo-packaging.csv \
    --report /reports/coin-photo-packaging.json --cache-dir /reports/ukraine-cache
```

CSV — по строке на каждую запись общего украинского каталога с
официальным фото, плюс безусловно все `Ми сильні. Ми разом.%`, даже без
фото (чтобы ни одна не выпала из отчёта — проверить, что все, сколько их
сейчас, там есть). `verdict`: `coin` / `packaging` / `no-photo`. Для «Ми
сильні» колонка `replacementUrl` заполнена автоматически — сопоставлено с
чистым аверсом/реверсом на ua-coins.info (все двенадцать областей
проверены вживую при написании кода, включая три новые). Для прочей
упаковки (если найдётся) колонка пустая — если знаете чистый источник,
впишите URL страницы `ua-coins.info` сами; если нет, оставьте пустой —
эта строка не будет тронута шагом 5.

**СТОП-ТОЧКА.** Открыть CSV. Против строк, которые заменить, поставить
`yes` в колонке `decision` (нужен непустой `replacementUrl` — иначе шаг 5
эту строку пропустит).

### Шаг 5 (apply) — заменить фото по ревью

```bash
docker compose run --rm -v "$PWD/migration-reports:/reports" \
  api python scripts/scan_coin_photo_packaging.py --apply \
    --apply-review /reports/coin-photo-packaging.csv \
    --report /reports/coin-photo-packaging-apply.json --cache-dir /reports/ukraine-cache
```

Для каждой строки `yes`: скачивает аверс/реверс с `replacementUrl`,
прогоняет через тот же срез фона, что и весь остальной украинский
конвейер (с тем же guard-ом — уже прозрачное или некруглое фото не
трогает), удаляет старые фото записи (любого источника — `nbu`/
`ua_coins`/`manual`) и сохраняет новые под `source = ua_coins`. Отчёт:
`replaced`/`failed`. Оригиналы роликов отдельно не хранились и раньше
(`docs/05-integrations.md`, раздел 9 — «Оригиналы не хранятся»), так что
откатывать физически нечего; но пока `--apply` не запущен, ничего не
меняется — можно вернуться к CSV и поправить решение сколько угодно раз.

## Проверка после обоих блоков

- В каталоге все монеты `Ми сильні. Ми разом.%` — с `series_id`, не
  `NULL` (проверить `SELECT count(*) FROM catalog_items WHERE
  title_original LIKE 'Ми сильні. Ми разом.%' AND series_id IS NULL` — 0
  строк).
- Карточки и «Серії» на фронте — чистые фото монет, не ролики, в обеих
  темах (глазами).
