# Публичный каталог и гостевой режим

## Исследование и решение

- `ProtectedRoute` закрывал весь `AppLayout`; `/` отправлял в `/collection`. `AuthProvider` восстанавливает сессию по refresh-cookie, API-клиент хранит access token в памяти и обновляет его при 401. React Query кэшировал каталог, карточки, цены и dashboard по отдельным ключам, но ключи не учитывали смену аккаунта.
- `CatalogService` и `CatalogRepository` совмещают общий каталог, личные записи, владение, суммы покупок, рыночные снимки и ссылки источников. `CatalogListItem`/`CatalogCard` содержат все эти поля. Отдельный `GET /catalog/{id}/prices` и личные `/collection`, `/bootstrap`, `/expenses`, `/settings`, admin и мутации уже требуют `CurrentUser`.
- Публичны характеристики общей подтверждённой позиции: названия, страна, серия, год, номинал, материал, тираж, размеры, изображения публичного происхождения и описания. Личны `created_by`, `owned`, экземпляры, покупки, заметки и архивные состояния. Цена, источник, URL и история цен доступны только после входа.
- Открыты существующие `/catalog`, `/catalog/{id}` и нужные каталогом справочники. Они используют `OptionalCurrentUser` только в этих маршрутах. Гостевые чтения идут через `PublicCatalogRepository`, который не соединяет таблицы цен и коллекции, и через явные схемы `PublicCatalogListItem`/`PublicCatalogCard`. Неавторизованные персональные фильтры отклоняются. Авторизованные маршруты и ответы сохраняют прежний сервис и схему.
- В React Router открыты общий layout, каталог, карточка и корень коллекции. Корень отправляет гостя в каталог, вошедшего пользователя в коллекцию. Прочие личные маршруты остаются под `ProtectedRoute`. UI гостя использует те же каталог, карточку, фильтры и виды; цена получает компактный закрытый вид, добавление — диалог входа, `/collection` — пустой обзор без вымышленных данных. При смене пользователя React Query кэш очищается.
- Вход сохраняет исходный путь через router state. После регистрации путь можно восстановить через sessionStorage до подтверждения email; это локальная подсказка навигации, не источник полномочий.

## Безопасность и ограничения

Сервер отклоняет гостевые `scope=own`, `owned`, `archived` и персональные сортировки. Цены и личные данные не сериализуются в публичные ответы. Все мутации и личные endpoint по-прежнему требуют Bearer; admin endpoint также проверяют роль. Клиентская маршрутизация не служит механизмом защиты.

Существующий Redis rate limiter теперь ограничивает только анонимное чтение: 300 запросов списка/карточек в минуту на IP, 90 поисковых запросов и 300 запросов справочников в минуту. Авторизованное чтение не ограничивается этими порогами. При превышении сервер отвечает 429 с `Retry-After`. Метрика реальной нагрузки позволит скорректировать пороги.

Во время выкладки статики после подъёма API скрипт `frontend/scripts/prerender-catalog.mjs` читает анонимный `/catalog`, создаёт HTML по `/catalog/:id`, каталог, `sitemap.xml` и `robots.txt`. Из публичного API выбираются только название и numismatic-характеристики; цены и URL источников в HTML не попадают. React использует те же URL и заменяет подготовленное содержимое при запуске. Индекс новых монет обновляется при следующей выкладке; если нужна немедленная индексация без деплоя, понадобится отдельное фоновое обновление. Центральный Caddy на сервере живёт вне репозитория: его статический `try_files` нужно привести к варианту в `Caddyfile`/`docs/10-infra.md`, чтобы новые файлы отдавались по прямым URL.

## Проверки

Регрессии должны покрывать публичные list/card и отсутствие ценовых полей, личные фильтры, защищённые prices/collection/mutations/admin; в UI — гостевой корень, каталог и карточку, закрытую цену, диалог добавления, обзор коллекции, заголовок и сохранение авторизованного поведения. Существующие проверки каталога, справочников, коллекции и auth должны продолжать проходить.
