# Команды владельца — сторож и уведомление о регистрации (2026-09-23)

Две небольшие задачи из части 1 и части 3 этапа 4.6 (`docs/13-admin.md`, `docs/11-roadmap.md`):
сторож пропавших прогонов и уведомление в телеграм о новом пользователе. Код и тесты готовы,
миграций нет, новых секретов нет — оба используют то, что уже настроено в части 1
(`TELEGRAM_BOT_TOKEN`, хотя бы один привязанный админский чат).

## Что изменилось

- `backend/scripts/watchdog.py` — новый скрипт: сверяет время последнего прогона трёх
  известных задач (`update-prices`, `update-rates`, `nbu-catalog-sync`) с ожидаемым
  интервалом и шлёт одно сообщение в телеграм на все просроченные разом. Молчит, если всё
  в порядке.
- Уведомление о новом пользователе — встроено в существующие эндпоинты
  (`/auth/verify-email`, `/auth/google/callback`), отдельной выкладки не требует: попадёт на
  сервер обычным пуском в `main` вместе с остальным кодом.

## 1. Выкладка кода

Обычный пуш в `main` — ничего особенного, миграций нет:

```bash
cd ~/Desktop/Work/coin_keeper
git push origin main   # или слияние ветки, если работа шла не в main напрямую
```

Дождаться зелёного CI и деплоя как обычно (`gh run list --limit 3`).

Уведомление о регистрации заработает сразу после выкладки — проверить, зарегистрировав
тестовый аккаунт (в чат придёт «🆕 Новий користувач: …»), если есть хотя бы один
привязанный админский чат.

## 2. Второй крон — сторож

Единственный ручной шаг. Скрипт живёт в образе `api`, который уже на сервере — просто
нужно, чтобы что-то регулярно его дёргало:

```bash
ssh coinkeeper
crontab -e
```

Добавить строку (пример — раз в 6 часов; можно чаще, спам не грозит: сообщение шлётся
только когда что-то реально просрочено, и заново на каждый прогон сторожа, пока не
починится):

```
0 */6 * * * cd ~/coinkeeper && docker compose exec -T api python scripts/watchdog.py >> /home/deploy/logs/watchdog.log 2>&1
```

Проверить, что строка сохранилась:

```bash
crontab -l
```

## 3. Проверка

Запустить руками, не дожидаясь крона:

```bash
ssh coinkeeper
cd ~/coinkeeper
docker compose exec -T api python scripts/watchdog.py
```

Ожидаемое на здоровой системе: `[watchdog] all jobs are within their expected window`,
без сообщения в телеграм. Чтобы увидеть настоящий алерт, не обязательно ждать —
`tests/test_watchdog.py` уже покрывает все случаи (никогда не запускалась, просрочена,
зависла в `running`, нет привязанного чата).

## Чего в этой части нет

Дедупликации повторных алертов — сторож шлёт сообщение при каждом прогоне, пока задача
остаётся просроченной. Решение осознанное (простота важнее): интервал крона сам
регулирует частоту, а тихий баг хуже повторяющегося напоминания.
